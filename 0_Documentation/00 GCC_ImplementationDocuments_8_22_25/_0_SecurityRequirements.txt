/cl1️⃣ Authentication Methods (Who Can Access?)
The API needs strong authentication mechanisms to validate requests.

Entity Type	Authentication Method	Example Usage
External Users with API Access	OAuth2 (Authorization Code Flow) or API Key	API users who manually retrieve or push certifications.
External Systems (Amazon, ERP, etc.)	OAuth2 (Client Credentials Flow) or API Key	Systems performing automated interactions.
Internal Admin Interface	JWT (JSON Web Tokens) with Role-Based Access Control (RBAC)	Internal users managing certifications.
Authentication Flows
✅ OAuth2 (Authorization Code Flow) → Used for external users who log in & access the API via a UI.
✅ OAuth2 (Client Credentials Flow) → Used for external systems (e.g., Amazon Marketplace) that authenticate using API credentials.
✅ API Keys → Used for both external users & systems, but limited to pre-defined permissions.
✅ JWT Tokens → Used internally for session-based authentication.

2️⃣ Authorization (What Can They Do?)
Once authenticated, requests need granular access control.

Access Type	Who Can Access?	Scope & Restrictions
Public Read Access (GET)	API Users & External Systems	Users can view certifications but cannot modify data.
Restricted Read Access (GET)	Authenticated Users Only	Can access specific certification data based on permissions.
Write Access (POST, PUT, DELETE)	Admins & Authorized API Users	Users must have explicit permissions to push new data.
System-to-System Access	External Systems Only	Requires whitelisted API keys or OAuth2 client credentials.
Authorization Implementation
✅ Role-Based Access Control (RBAC) → Enforce different access levels.
✅ Scopes in OAuth2 → Define what API keys or tokens can do (e.g., read:certifications, write:certifications).
✅ Fine-Grained Permissions → API requests must pass permission checks.

3️⃣ Security Best Practices
✅ API Gateway Security
Validates every request → Ensures only authenticated users & systems can pass through.
Routes based on permission levels → Only allows users to interact with permitted endpoints.
✅ Data Encryption
TLS (HTTPS-only) → All requests & responses must be encrypted.
Data at Rest Encryption → Database should store sensitive data securely.
✅ Rate Limiting & Throttling
Prevents API abuse by limiting requests per user/system.
Example:
External Users → 1000 API requests/hour
External Systems → 5000 API requests/hour
✅ Logging & Monitoring
Audit logs track every API call (who accessed what and when).
Monitoring tools (e.g., AWS CloudWatch, Datadog) detect anomalies.
