  ## What is ETL?



  **ETL** stands for **Extract, Transform, Load** - a data integration process that:

  - **Extracts** data from various source systems

  - **Transforms** the data into a suitable format

  - **Loads** the processed data into a target destination (data warehouse, database, etc.)



  ## The Three Phases of ETL



  ### 1. Extract Phase

  **Purpose**: Retrieve data from source systems



  **Common Data Sources**:

  - Relational databases (MySQL, PostgreSQL, SQL Server)

  - APIs and web services

  - CSV/Excel files

  - JSON/XML files

  - Cloud storage (S3, Google Cloud Storage)

  - Real-time streams (Kafka, Kinesis)



  **Extraction Methods**:

  - **Full extraction**: Complete data dump

  - **Incremental extraction**: Only new/changed data

  - **Real-time extraction**: Continuous data streaming



  ### 2. Transform Phase

  **Purpose**: Clean, validate, and structure data



  **Common Transformations**:

  - **Data cleaning**: Remove duplicates, handle missing values

  - **Data validation**: Check data quality and consistency

  - **Data formatting**: Standardize dates, currencies, text formats

  - **Data aggregation**: Sum, average, count operations

  - **Data enrichment**: Add calculated fields or lookup values

  - **Data filtering**: Remove irrelevant records

  - **Data type conversion**: Change data types as needed



  ### 3. Load Phase

  **Purpose**: Insert transformed data into target system



  **Loading Strategies**:

  - **Full load**: Replace all existing data

  - **Incremental load**: Add only new/changed records

  - **Upsert**: Update existing records or insert new ones

  ### Prerequisites


  ### Step 1: Extract Data

  ```python

  import pandas as pd

  import requests

  from sqlalchemy import create_engine



  # Extract from CSV file

  def extract_from_csv(file_path):

      return pd.read_csv(file_path)



  # Extract from API

  def extract_from_api(url):

      response = requests.get(url)

      return pd.DataFrame(response.json())



  # Extract from database

  def extract_from_database(connection_string, query):

      engine = create_engine(connection_string)

      return pd.read_sql(query, engine)



  # Example usage

  data = extract_from_csv('sales_data.csv')

  ```



  ### Step 2: Transform Data

  ```python

  def transform_data(df):

      # Data cleaning

      df = df.drop_duplicates()

      df = df.dropna(subset=['customer_id', 'amount'])

      

      # Data formatting

      df['date'] = pd.to_datetime(df['date'])

      df['amount'] = df['amount'].astype(float)

      

      # Data validation

      df = df[df['amount'] > 0]  # Remove negative amounts

      

      # Data enrichment

      df['year'] = df['date'].dt.year

      df['month'] = df['date'].dt.month

      df['total_with_tax'] = df['amount'] * 1.08

      

      # Data aggregation

      monthly_summary = df.groupby(['year', 'month']).agg({

          'amount': ['sum', 'mean', 'count'],

          'customer_id': 'nunique'

      }).round(2)

      

      return df, monthly_summary



  # Example usage

  clean_data, summary = transform_data(data)

  ```



  ### Step 3: Load Data

  ```python

  def load_to_database(df, table_name, connection_string):

      engine = create_engine(connection_string)

      df.to_sql(table_name, engine, if_exists='replace', index=False)

      print(f"Loaded {len(df)} records to {table_name}")



  def load_to_csv(df, file_path):

      df.to_csv(file_path, index=False)

      print(f"Data saved to {file_path}")



  # Example usage

  load_to_database(clean_data, 'sales_clean', 'postgresql://user:pass@localhost/db')

  load_to_csv(summary, 'monthly_summary.csv')

  ```



  ### Complete ETL Pipeline

  ```python

  def run_etl_pipeline():

      try:

          # Extract

          print("Extracting data...")

          raw_data = extract_from_csv('sales_data.csv')

          

          # Transform

          print("Transforming data...")

          clean_data, summary = transform_data(raw_data)

          

          # Load

          print("Loading data...")

          load_to_database(clean_data, 'sales_clean', connection_string)

          load_to_csv(summary, 'summary_report.csv')

          

          print("ETL pipeline completed successfully!")

          

      except Exception as e:

          print(f"ETL pipeline failed: {str(e)}")



  # Run the pipeline

  run_etl_pipeline()

  ```

  ```python

  from datetime import datetime, timedelta

  from airflow import DAG

  from airflow.operators.python_operator import PythonOperator

  from airflow.operators.bash_operator import BashOperator



  default_args = {

      'owner': 'data_team',

      'depends_on_past': False,

      'start_date': datetime(2024, 1, 1),

      'email_on_failure': True,

      'email_on_retry': False,

      'retries': 2,

      'retry_delay': timedelta(minutes=5)

  }



  dag = DAG(

      'daily_sales_etl',

      default_args=default_args,

      description='Daily sales data ETL pipeline',

      schedule_interval='@daily',

      catchup=False

  )



  def extract_task():

      # Your extraction logic here

      print("Extracting data from source systems...")



  def transform_task():

      # Your transformation logic here

      print("Transforming extracted data...")



  def load_task():

      # Your loading logic here

      print("Loading transformed data to warehouse...")



  # Define tasks

  extract = PythonOperator(

      task_id='extract_data',

      python_callable=extract_task,

      dag=dag

  )



  transform = PythonOperator(

      task_id='transform_data',

      python_callable=transform_task,

      dag=dag

  )



  load = PythonOperator(

      task_id='load_data',

      python_callable=load_task,

      dag=dag

  )



  # Set task dependencies

  extract >> transform >> load

  ```



  ## Tutorial 3: ETL with SQL



  ### Extract with SQL

  ```sql

  -- Extract from multiple tables

  SELECT 

      o.order_id,

      o.customer_id,

      o.order_date,

      oi.product_id,

      oi.quantity,

      oi.unit_price,

      p.product_name,

      c.customer_name

  FROM orders o

  JOIN order_items oi ON o.order_id = oi.order_id

  JOIN products p ON oi.product_id = p.product_id

  JOIN customers c ON o.customer_id = c.customer_id

  WHERE o.order_date >= '2024-01-01';

  ```



  ### Transform with SQL

  ```sql

  -- Create transformed view

  CREATE VIEW sales_summary AS

  SELECT 

      DATE_TRUNC('month', order_date) as month,

      customer_id,

      COUNT(DISTINCT order_id) as order_count,

      SUM(quantity * unit_price) as total_revenue,

      AVG(quantity * unit_price) as avg_order_value,

      CASE 

          WHEN SUM(quantity * unit_price) > 1000 THEN 'High Value'

          WHEN SUM(quantity * unit_price) > 500 THEN 'Medium Value'

          ELSE 'Low Value'

      END as customer_segment

  FROM sales_raw

  GROUP BY DATE_TRUNC('month', order_date), customer_id;

  ```



  ### Load with SQL

  ```sql

  -- Insert transformed data

  INSERT INTO sales_warehouse (

      month, customer_id, order_count, total_revenue, 

      avg_order_value, customer_segment, created_at

  )

  SELECT 

      month, customer_id, order_count, total_revenue,

      avg_order_value, customer_segment, CURRENT_TIMESTAMP

  FROM sales_summary

  ON CONFLICT (month, customer_id) 

  DO UPDATE SET

      order_count = EXCLUDED.order_count,

      total_revenue = EXCLUDED.total_revenue,

      avg_order_value = EXCLUDED.avg_order_value,

      customer_segment = EXCLUDED.customer_segment,

      updated_at = CURRENT_TIMESTAMP;

  ```

  - **Validate data types** and formats

  - **Check for nulls** and missing values

  - **Verify business rules** and constraints

  - **Monitor data completeness** and accuracy



  ### 2. Performance Optimization

  - **Use incremental loading** when possible

  - **Implement proper indexing** on target tables

  - **Optimize SQL queries** and transformations

  - **Parallelize processing** for large datasets



  ### 3. Error Handling

  - **Implement comprehensive logging**

  - **Set up alerts** for failures

  - **Create rollback mechanisms**

  - **Monitor data lineage**



  ### 4. Security

  - **Encrypt sensitive data** in transit and at rest

  - **Use secure connections** for data transfer

  - **Implement access controls** and authentication

  - **Audit data access** and modifications



  ### 5. Scalability

  - **Design for future growth**

  - **Use cloud-native solutions** when appropriate

  - **Implement horizontal scaling**

  - **Consider real-time vs batch processing**



  ## Common ETL Patterns



  ### 1. Slowly Changing Dimensions (SCD)

  ```sql

  -- Type 2 SCD: Keep history of changes

  UPDATE customer_dim 

  SET end_date = CURRENT_DATE, is_current = FALSE

  WHERE customer_id = '123' AND is_current = TRUE;



  INSERT INTO customer_dim (

      customer_id, customer_name, address, start_date, end_date, is_current

  ) VALUES (

      '123', 'Updated Name', 'New Address', CURRENT_DATE, '9999-12-31', TRUE

  );

  ```



  ### 2. Change Data Capture (CDC)

  ```python

  def process_cdc_changes(source_table, target_table):

      # Identify changed records

      changes = extract_changes(source_table)

      

      for change in changes:

          if change['operation'] == 'INSERT':

              insert_record(target_table, change['data'])

          elif change['operation'] == 'UPDATE':

              update_record(target_table, change['data'])

          elif change['operation'] == 'DELETE':

              delete_record(target_table, change['key'])

  ```



  ### 3. Data Deduplication

  ```python

  def deduplicate_records(df, key_columns, strategy='latest'):

      if strategy == 'latest':

          return df.sort_values('timestamp').drop_duplicates(

              subset=key_columns, keep='last'

          )

      elif strategy == 'first':

          return df.drop_duplicates(subset=key_columns, keep='first')

  ```

  ### Key Metrics to Monitor

  - **Data freshness**: How recent is your data?

  - **Data completeness**: Are all expected records present?

  - **Processing time**: How long does ETL take?

  - **Error rates**: What percentage of records fail?

  2. **Slow performance**: Optimize queries and add indexes

  3. **Data quality issues**: Implement validation rules

  4. **Connection timeouts**: Add retry logic

  5. **Schema changes**: Implement flexible schema handling
