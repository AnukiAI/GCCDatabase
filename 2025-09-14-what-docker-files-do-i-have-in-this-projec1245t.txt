● Based on your Dockerfile and .dockerignore, here's exactly what gets
  included in your Docker image:

  What's IN the Image:

  1. Published Application Files (from dotnet publish):

  - GCCWebApp.dll - Main application executable
  - All runtime dependencies - .NET Core libraries and NuGet packages
  - Configuration files:
    - appsettings.json
    - appsettings.Development.json (if exists)
    - web.config (if generated)

  2. Static Web Assets (wwwroot/ folder):

  - CSS files - Bootstrap, custom styles
  - JavaScript files - jQuery, site scripts
  - Images - Including your logos (both GCCLogo.png and gcclogo.png
  after the fix)
  - Fonts - Any web fonts
  - Static HTML files - Any static content

  3. Views and Templates:

  - All Razor views (.cshtml files)
  - Layout files - _Layout.cshtml, etc.
  - Partial views - _ViewStart.cshtml, _ViewImports.cshtml

  4. Additional Runtime Files:

  - Empty /app/logs directory - Created for application logs
  - Base Linux image - ASP.NET Core runtime environment
  - Non-root user account - appuser for security

  What's EXCLUDED from the Image:

  Source Code & Development Files:

  - Source .cs files
  - Project files (.csproj, .sln)
  - bin/ and obj/ folders
  - Visual Studio files (.vs/, .vscode/)

  Documentation & Non-Runtime Files:

  - All .md files (documentation)
  - docs/ folder
  - Documentation/ folder
  - Your Docker files themselves
  - Git files (.git/, .gitignore)

  Development & Testing:

  - Test projects and results
  - Debug symbols (unless included in publish)
  - Development databases (.db, .sqlite)
  - Log files from development

  Build Artifacts:

  - NuGet package cache
  - Build output folders
  - Temporary files

  Size Optimization:

  Your Docker image uses multi-stage builds, so:
  1. Build stage - Has full .NET SDK (~700MB) but gets discarded
  2. Final stage - Only ASP.NET runtime (~200MB) + your app

  The final image contains only what's needed to run your application -
   no source code, no development tools, no build artifacts.

  So to answer your question: No, it's not just the release folder.
  It's the published application output plus the web assets (wwwroot),
  views, and runtime configuration - but no source code or development
  files.
