API Partner Access & Security Analysis

Amazon ASIN Integration and External Partner Data Access

Date: October 15, 2025 | Status: Security Audit Complete

Executive Summary

This document analyzes how Amazon and other external partners access certificate data, specifically ASINs (Amazon Standard Identification Numbers) and other product identifiers through the GCC Web Application API endpoints.

Key Finding: The application has multiple API access methods with varying security levels. Some endpoints designed for partner access are currently public without authentication, which may be intentional for partner integration but requires clarification.
Data Model: The application supports multiple product identifiers per certificate including ASIN, UPC, GTIN, EAN, ISBN, SKU, and MPN. Each certificate can have hundreds of ASINs, enabling comprehensive Amazon marketplace integration.

3. Amazon Integration Flow

Typical Amazon ASIN Lookup Flow

Step 1: API Request
Amazon service makes HTTP GET request
GET /api/CertificateTileExternal?partner=Amazon&search=B08N5WRWNW
↓
Step 2: Authentication (Optional)
Include X-API-Key header for authenticated access
Or rely on public access with partner claim from cookie/JWT
↓
Step 3: Partner Filtering
Controller extracts partner from claims: "Amazon"
Query filters: WHERE Partner = 'Amazon' OR Partner IS NULL
↓
Step 4: ASIN Search
Search includes CertificateProductId table
Matches ASIN values against ProductIdValue field
↓
Step 5: Response
Returns certificates with associated ASINs
Only active certificates, no internal status fields

7. Summary & Action Items

How Amazon Currently Accesses ASINs:

Current State:
  • ASINs stored in CertificateProductId table with many-to-many relationship
  • Public access via /api/CertificateTileExternal (no authentication)
  • Authenticated access via /api/v1/certificates (API Key required)
  • Partner filtering based on "partner" claim in user identity
  • Only active certificates returned to external partners

Recommended Path Forward:

For Production Amazon Integration:
  1. Use API v1 with API Key authentication (most secure)
  2. Create dedicated Amazon API key with:
    • IP whitelist: Amazon AWS IP ranges
    • Scopes: certificates:read, certificates:search
    • Rate limit: 5000 requests/hour
    • Partner claim: "Amazon"
  3. Amazon includes X-API-Key header in all requests
  4. Responses automatically filtered to Amazon + public certificates only

Critical Security Fixes Required:

High Priority:
  1. Secure CertificatesApiController.ExportCertificates (line 404)
  2. Secure CertificatesApiController.DownloadCertificateFile (line 369)
  3. Add rate limiting to CertificateTileExternalApiController
  4. Decide on authentication strategy for external partner API

Questions to Resolve:

Business/Architecture Decisions Needed:
  • Should CertificateTileExternalApiController remain public or require API keys?
  • What is the acceptable rate limit for unauthenticated ASIN searches?
  • Should Amazon have access to all certificates or only those marked with Partner="Amazon"?
  • Do certificate PDFs need to be downloadable without authentication?
  • Should ASINs be searchable by the public or only by authenticated partners?
