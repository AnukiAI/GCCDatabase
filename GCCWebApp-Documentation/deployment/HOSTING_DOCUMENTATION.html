Executive Overview

Application Summary

The GreenCircle Certified Database is an enterprise-grade ASP.NET Core 8.0 MVC web application designed to manage environmental certifications and certificates. The application provides comprehensive certificate lifecycle management, public certificate viewing, partner API access, and administrative capabilities.

Key Features

  • Public certificate tile view with infinite scroll
  • Advanced search and filtering
  • Product ID management (ASINs, UPCs, GTINs)
  • PDF certificate generation
  • RESTful API with rate limiting
  • Role-based access control (Admin, Analyst, External)
  • Two-factor authentication
  • Excel/CSV export capabilities

Technical Stack

  • Framework: ASP.NET Core 8.0 MVC
  • Database: SQL Server (production)
  • ORM: Entity Framework Core 8.0
  • Authentication: Cookie + JWT Bearer
  • PDF Generation: QuestPDF
  • Frontend: Bootstrap 5, jQuery
  • API: RESTful with versioning

Deployment Status

  • Publish Status: ✅ Ready
  • Tests: ✅ Passing
  • Security: ✅ Hardened
  • Performance: ✅ Optimized
  • Documentation: ✅ Complete

Deployment Process

Step 1: Build and Publish

Using Command Line

# Navigate to project directory cd "GCCWebApp" # Restore NuGet packages dotnet restore # Build in Release mode dotnet build -c Release # Publish using AccuWeb profile dotnet publish -c Release -p:PublishProfile=AccuWebProduction
Publish Output Location

Directory: bin\Release\net8.0\win-x64\publish\

All files in this directory must be uploaded to the AccuWeb server.

Using Visual Studio

  1. Right-click on GCCWebApp project in Solution Explorer
  2. Select Publish...
  3. Choose AccuWebProduction profile
  4. Click Publish
  5. Wait for build and publish to complete

Verify Published Files

GCCWebApp.dll - Main application assembly
web.config - IIS configuration file
appsettings.json - Base configuration
appsettings.Production.json - Production overrides
wwwroot/ folder - Static files (CSS, JS, images)
All DLL dependencies - Third-party libraries

Step 2: Upload to AccuWeb

Method 1: FTP/SFTP Upload

  1. Connect to AccuWeb FTP server
  2. Navigate to web root (wwwroot or httpdocs)
  3. Upload ALL files from publish folder
  4. Preserve folder structure
  5. Verify all files transferred

Method 2: File Manager (Recommended)

  1. Log into AccuWeb control panel
  2. Open File Manager
  3. Create ZIP of publish folder
  4. Upload ZIP file
  5. Extract ZIP on server
Important: File Permissions

Ensure the IIS Application Pool identity has read/execute permissions on all uploaded files and write permissions on the logs folder.

Step 3: Database Setup

Option A: Automatic Migration (Recommended)

Auto-Migration Enabled

The application is configured to automatically apply database migrations on first startup in Production environment. No manual migration required.

Option B: Manual Migration

# From local machine with connection to production database dotnet ef database update --connection "Server=your-prod-server;Database=GCCDatabase;User Id=...;Password=...;"

Database Initialization

On first run, the application will:

  • Auto-detect SQL Server from connection string
  • Apply all pending migrations
  • Create all required tables, indexes, and constraints
  • NOT seed test data (Production environment)
  • Log initialization results to stdout logs

Step 4: IIS Configuration

Application Pool Setup

Navigate to Application Pools in IIS Manager
Create new pool or select existing
Set .NET CLR Version to No Managed Code
Set Managed Pipeline Mode to Integrated
Set Enable 32-bit Applications to False
Start the application pool

Website Configuration

Assign application pool to website
Set physical path to publish folder
Configure HTTPS binding with SSL certificate
Verify HTTP to HTTPS redirect working

Step 5: Post-Deployment Verification

Essential Endpoint Tests

Endpoint Expected Result Status
https://yourdomain.com/ Certificate tile view or login redirect ☐ Verified
https://yourdomain.com/health JSON health status (200 OK) ☐ Verified
https://yourdomain.com/Account/Login Login page displays ☐ Verified
http://yourdomain.com/ Redirects to HTTPS ☐ Verified
https://yourdomain.com/swagger 404 or redirect (disabled in production) ☐ Verified

Security Header Verification

Open browser Developer Tools (F12) → Network tab and verify the following security headers are present:

X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
Strict-Transport-Security (HSTS)
Content-Security-Policy

Step 6: Create Admin User

Create the first administrator account using SQL Server Management Studio or Azure Data Studio:

-- Create admin user (use BCrypt for password hash) INSERT INTO Users (Email, PasswordHash, FirstName, LastName, IsActive, CreatedDate) VALUES ( 'admin@greencirclecertified.com', '$2a$11$...', -- BCrypt hash of password 'Admin', 'User', 1, GETDATE() ); -- Assign Admin role INSERT INTO UserRoles (UserId, RoleId) VALUES ( SCOPE_IDENTITY(), (SELECT Id FROM Roles WHERE Name = 'Admin') );
Password Hash Generation

Use BCrypt.Net to generate password hashes. Do not store plain-text passwords. Minimum password requirements: 12 characters, uppercase, lowercase, digit, special character.

Configuration Guide

Required Environment Variables

Critical Security Configuration

NEVER commit production secrets to source control. Use environment variables or AccuWeb's secure configuration system.

Variable Name Example Value Description Status
ASPNETCORE_ENVIRONMENT Production Sets application environment Required
GCC_JWT_SECRET (64+ random characters) JWT signing key (MUST be unique) Critical
ConnectionStrings__DefaultConnection Server=...;Database=... SQL Server connection string Required
SmtpSettings__Host smtp.gmail.com SMTP server for emails (2FA) Optional
SmtpSettings__Username noreply@yourdomain.com SMTP authentication username Optional
SmtpSettings__Password (SMTP password/app password) SMTP authentication password Optional

SQL Server Connection String

Format

Server={server-address}; Database=GCCDatabase; User Id={username}; Password={password}; Encrypt=True; TrustServerCertificate=False; MultipleActiveResultSets=true; Connection Timeout=30;

Connection String Examples

SQL Server (Windows Auth)

Server=localhost; Database=GCCDatabase; Trusted_Connection=True; MultipleActiveResultSets=true;

SQL Server (SQL Auth)

Server=server.database.windows.net; Database=GCCDatabase; User Id=gcc_admin; Password=YourPassword123!; Encrypt=True;

Azure SQL Database

Server=tcp:gccdb.database.windows.net; Database=GCCDatabase; User Id=gcc_admin@gccdb; Password=YourPassword123!; Encrypt=True;

Configuration Methods

Method 1: AccuWeb Control Panel

Most Secure ✅ Recommended

  1. Log into AccuWeb control panel
  2. Navigate to your application
  3. Go to Application Settings
  4. Add environment variables as key-value pairs
  5. Save and restart application pool

Method 2: web.config

Server-Side Configuration

<aspNetCore> <environmentVariables> <environmentVariable name="GCC_JWT_SECRET" value="your-secret" /> <environmentVariable name="ConnectionStrings__DefaultConnection" value="Server=..." /> </environmentVariables> </aspNetCore>

Method 3: appsettings.Production.json

Pre-Deployment Edit

Edit appsettings.Production.json before publishing. Less secure for credentials but acceptable for non-sensitive configuration.

Security Warning

Do not store database passwords or JWT secrets in appsettings.Production.json. Use environment variables instead.

Production Configuration Settings

Rate Limiting (Already Configured)

The application includes pre-configured rate limiting to protect against abuse:

Endpoint Pattern Limit Period Purpose
*/api/* 60 requests 1 minute Prevent rapid API abuse
*/api/* 1,000 requests 1 hour Hourly API quota
*/api/* 5,000 requests 1 day Daily API quota
*/api/*/auth/login 5 requests 1 minute Brute force protection
*/api/*/auth/login 20 requests 1 hour Login attempt limit
Adjusting Rate Limits

Rate limits can be adjusted in appsettings.Production.json under the IpRateLimiting section. Increase limits if legitimate users are being blocked.

When to Upgrade Hosting

Upgrade Triggers

Consider upgrading your hosting plan if you observe any of the following:

Response Time > 3 seconds consistently during normal traffic
CPU usage > 80% for extended periods
Memory usage > 90% causing frequent app pool recycles
Frequent 503 errors (service unavailable) during peak times
Database connection timeouts occurring regularly
Rate limits exceeded by legitimate users frequently
Bandwidth cap reached mid-month
Traffic exceeds 10,000 visits/month

Security Configuration

Security Checklist

Production Security Requirements

All items in this checklist must be verified before going live in production.

JWT secret is unique, random, and 64+ characters (currently set and secure)
Database credentials are strong and not in source control
HTTPS is enforced - HTTP redirects to HTTPS
Security headers present in all responses (HSTS, CSP, X-Frame-Options, etc.)
Swagger endpoint disabled in production
Detailed error messages disabled - generic errors shown to users
Rate limiting active and configured appropriately
SQL Server connection uses encryption (Encrypt=True)
Sensitive file extensions blocked (.db, .config, .log, .bak)
ASPNETCORE_ENVIRONMENT=Production set correctly
CSRF protection enabled for all forms
XSS protection enabled in security headers
