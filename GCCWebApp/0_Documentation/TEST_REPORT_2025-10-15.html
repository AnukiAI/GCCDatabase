Critical Issues BLOCKER

#1 - SQL Server Logon Trigger Blocking Database Access CRITICAL

Severity: Critical - Application Cannot Function

Impact: Blocks all database operations, preventing data loading

Description: SQL Server LocalDB has a logon trigger that blocks the Windows user POINTSOLVE\swest from accessing any database, including the master database.

Error Message:

Microsoft.Data.SqlClient.SqlException (0x80131904):
Logon failed for login 'POINTSOLVE\swest' due to trigger execution.
Changed database context to 'master'.
Changed language setting to us_english.
Error Number:17892,State:1,Class:14

Affected Areas:

  • Database initialization and seeding
  • Entity Framework migrations
  • All database queries and operations
  • Certificate data loading
  • User authentication

Recommended Solutions:

  1. Immediate Fix: Use SQL Server's Dedicated Administrator Connection (DAC) to connect and disable the logon trigger: 
    sqlcmd -S "admin:(localdb)\mssqllocaldb" -Q "DISABLE TRIGGER ALL ON ALL SERVER"
  2. Alternative: Identify and drop the specific logon trigger: 
    -- Using DAC
sqlcmd -S "admin:(localdb)\mssqllocaldb"
SELECT name FROM sys.server_triggers WHERE type = 'TR';
DROP TRIGGER [trigger_name] ON ALL SERVER;
  3. Temporary Workaround: Use SQLite for development (requires migration regeneration)
  4. Long-term: Recreate SQL Server LocalDB instance without triggers: 
    sqllocaldb delete MSSQLLocalDB
sqllocaldb create MSSQLLocalDB
sqllocaldb start MSSQLLocalDB

High Priority Issues HIGH

#2 - Database Migrations Incompatible with SQLite HIGH

Severity: High - Blocks Alternative Database Strategy

Impact: Cannot use SQLite as fallback database

Description: All Entity Framework migrations were generated for SQL Server and use SQL Server-specific data types (int, nvarchar, datetime2, bit) that are incompatible with SQLite's type system.

Error Message:

SQLite Error 1: 'AUTOINCREMENT is only allowed on an INTEGER PRIMARY KEY'.
Migration uses: int NOT NULL CONSTRAINT "PK_Users" PRIMARY KEY AUTOINCREMENT
SQLite expects: INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT

Recommended Solutions:

  1. Regenerate migrations specifically for SQLite development environment
  2. Use database-provider-aware migrations with conditional logic
  3. Maintain separate migration sets for SQL Server (production) and SQLite (development)
#3 - Database Does Not Exist HIGH

Severity: High - No Data Available

Impact: Cannot load any certificate data or user information

Recommended Solutions:

  1. Fix Issue #1 first to enable database access
  2. Run dotnet ef database update to create database and apply migrations
  3. Verify database creation with sqlcmd -S "(localdb)\mssqllocaldb" -Q "SELECT name FROM sys.databases"
#4 - Configuration Mismatch Between Development and Production HIGH

Severity: High - Configuration Inconsistency

Impact: Different database providers in different environments

Description: The application is configured to use different database providers:

  • Development: Initially SQLite, then changed to SQL Server LocalDB
  • Production: SQL Server on remote host (68.71.129.120:1533)
  • Design-time Factory: Hardcoded to SQL Server LocalDB

Files Modified:

  • appsettings.Development.json - Changed from SQLite to SQL Server
  • Data/ApplicationDbContextFactory.cs - Changed from SQL Server to SQLite

Recommended Solutions:

  1. Standardize on one database provider for all environments (SQL Server recommended)
  2. Update ApplicationDbContextFactory to read from appsettings.json
  3. Document database requirements clearly in CLAUDE.md
