Role Management Help Guide

Complete guide to understanding and managing roles and permissions in the GCC Database

Overview

The GCC Database uses a granular role-based access control (RBAC) system with 24 individual permissions organized into 6 categories. Roles are assigned to users and determine what actions they can perform within the system.

Permission Categories

Certificates

View, create, edit, delete, workflow

Data

Export, import, reports, audit logs

Administration

Users, roles, companies, partners

API Access

Read, write, delete via API

Products

View and manage product catalog

System

Settings, cert types, custom fields

Role Types

System Roles come pre-configured (Admin, Analyst, External, Public). Custom Roles can be created by administrators for specialized needs like Partner access or API-only integrations.

Managing Roles

Creating a New Role

1

Navigate to Role Management

Go to Admin > Role Management from the main navigation menu.

2

Click Add Role

Click the Add Role button in the top right corner of the page.

3

Enter Role Details

Provide a Role Name and optional Description to help identify the role's purpose.

4

Select Permissions

Check the permissions required for this role. Use Select All or Clear All buttons for quick selection. Permissions are grouped by category for easy navigation.

5

Save the Role

Click Save to create the role. The new role will appear in the roles list and can be assigned to users.

Important Notes

The Admin role cannot be deleted or modified to remove critical permissions. Roles with assigned users should have users reassigned before deletion.

Best Practices

Principle of Least Privilege

Assign users the minimum permissions necessary to perform their job functions. This reduces security risks and prevents accidental data modifications.

Use Custom Roles for Specific Needs

Instead of granting excessive permissions with a built-in role, create a custom role with only the required permissions tailored to specific job functions.

Regular Access Reviews

Periodically review user role assignments to ensure they remain appropriate. Remove access for users who have changed roles or left the organization.

Document Custom Roles

When creating custom roles, use clear names and descriptions so other administrators understand their purpose without needing to review all permissions.

Common Scenarios

New Certification Analyst

Recommended: Analyst
  • Can create and edit certificates
  • Can manage workflow states
  • Cannot delete certificates
  • Cannot access admin functions

Amazon Climate Pledge Integration

Recommended: Partner
  • View-only access to certificates
  • API read access for data sync
  • Export capability for reporting
  • No write or delete permissions

Client Company Representative

Recommended: External
  • View only their company's certificates
  • View only their company's products
  • Can export their own data
  • Cannot see other companies' data

Automated Sync Service

Recommended: API Integration
  • API read/write access
  • No web UI access needed
  • Programmatic certificate lookups
  • Data synchronization capabilities

Troubleshooting

User Cannot Access Expected Features
  1. Verify the user's assigned role in Admin > User Management
  2. Check the role's permissions in Admin > Role Management
  3. Ensure the specific permission for the desired feature is enabled
  4. For External users, verify they are associated with the correct company
Permission Changes Not Taking Effect
  1. User may need to log out and log back in for changes to take effect
  2. Check if the change was saved successfully (look for confirmation message)
  3. Clear browser cache if issues persist
  4. Verify no conflicting permissions exist at the user level
Cannot Delete a Role
  1. Ensure no users are currently assigned to the role
  2. Verify you have the "Manage Roles" permission
  3. Note that the Admin role cannot be deleted (this is by design)
  4. System roles may have restrictions on deletion
