  Table: AuditHistory
  - Id (int, PK, identity)
  - EntityType (nvarchar(100), required) - "Product", "Company", "Tag", etc.
  - EntityId (nvarchar(50), required) - Primary key of changed entity
  - EntityName (nvarchar(255), nullable) - Denormalized name for history
  - Action (nvarchar(20), required) - "CREATE", "UPDATE", "DELETE",
  "RESTORE"
  - FieldName (nvarchar(100), nullable) - Specific field changed (null for
  CREATE/DELETE)
  - OldValue (nvarchar(max), nullable) - Previous value (JSON for complex)
  - NewValue (nvarchar(max), nullable) - New value (JSON for complex)
  - ChangedBy (int, FK Users) - User who made change
  - ChangedByUsername (nvarchar(255)) - Denormalized username
  - ChangedAt (datetime2, required) - Timestamp UTC
  - IpAddress (nvarchar(50), nullable)
  - UserAgent (nvarchar(500), nullable)
  - ChangeSource (nvarchar(50)) - "Web UI", "API", "Import", "Automated"
  - Reason (nvarchar(1000), nullable) - User-provided reason
  - SessionId (nvarchar(100), nullable) - For correlation

  Indexes:
  - IX_AuditHistory_EntityType_EntityId_ChangedAt (composite)
  - IX_AuditHistory_ChangedBy
  - IX_AuditHistory_ChangedAt
  - IX_AuditHistory_Action

  Table: UserAuditHistory
  - Id (int, PK, identity)
  - UserId (int, FK Users, required)
  - Username (nvarchar(255)) - Denormalized

  "ROLE_ASSIGNED", "ROLE_REMOVED", "2FA_ENABLED", "2FA_DISABLED",

  - Details (nvarchar(max), nullable) - JSON details

  - Timestamp (datetime2, required)
  - IpAddress (nvarchar(50))

  What Are Temporal Tables?

  SQL Server automatically maintains complete history of every change to a
  table:
  - Zero code changes in your application
  - Automatic - every UPDATE/DELETE is captured in a shadow history table
  - Point-in-time queries - "Show me Product #123 as it existed on Oct 15,
  2024"
  - Cannot be bypassed - even SQL scripts, migrations, and direct DB access
  are captured
  - Built-in, tested, reliable

  Example Setup (5 minutes per table):

  -- Enable temporal table on Products
  ALTER TABLE Products
  ADD
      ValidFrom DATETIME2 GENERATED ALWAYS AS ROW START NOT NULL DEFAULT
  SYSUTCDATETIME(),
      ValidTo DATETIME2 GENERATED ALWAYS AS ROW END NOT NULL DEFAULT
  '9999-12-31 23:59:59.9999999',
      PERIOD FOR SYSTEM_TIME (ValidFrom, ValidTo);

  ALTER TABLE Products
  SET (SYSTEM_VERSIONING = ON (HISTORY_TABLE = dbo.ProductsHistory));

  That's it! SQL Server now automatically tracks every change to Products.

  Querying History:

  -- Current state
  SELECT * FROM Products WHERE Id = 123;

  -- History at specific time
  SELECT * FROM Products
  FOR SYSTEM_TIME AS OF '2024-10-15 10:30:00'
  WHERE Id = 123;

  -- All changes ever made
  SELECT * FROM Products
  FOR SYSTEM_TIME ALL
  WHERE Id = 123
  ORDER BY ValidFrom DESC;

  -- Who changed what between dates
  SELECT * FROM Products
  FOR SYSTEM_TIME BETWEEN '2024-10-01' AND '2024-10-31'
  WHERE Id = 123;
