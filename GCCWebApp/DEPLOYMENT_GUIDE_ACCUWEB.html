1 Prerequisites

AccuWeb Server Requirements

  • .NET 8.0 Runtime (ASP.NET Core)
  • Windows Server with IIS 10+
  • ASP.NET Core Module V2 (ANCM)
  • URL Rewrite Module for IIS
  • SQL Server Database

Local Development Requirements

  • .NET 8.0 SDK
  • Visual Studio 2022 or VS Code
  • AccuWeb Control Panel Access
  • FTP/SFTP Client (optional)
✓ Status: All prerequisite checks completed. Application is production-ready.

2 Build and Publish

Using Command Line (Recommended)

cd "GCCWebApp" dotnet publish -c Release -p:PublishProfile=AccuWebProduction

Using Visual Studio

  1. Right-click on GCCWebApp project
  2. Select Publish
  3. Choose AccuWebProduction profile
  4. Click Publish
📁 Published Location: bin\Release\net8.0\win-x64\publish\

Verify Published Files

GCCWebApp.dll (main application)
web.config (IIS configuration)
appsettings.Production.json
wwwroot/ folder (CSS, JS, images)
All dependency DLLs

3 Configuration CRITICAL

⚠ SECURITY WARNING: Never commit production secrets to source control. Use environment variables or AccuWeb's secure configuration system.

Required Configuration Items

Setting Variable Name Example/Format Status
Environment ASPNETCORE_ENVIRONMENT Production REQUIRED
JWT Secret GCC_JWT_SECRET 64+ random characters REQUIRED
Database Connection ConnectionStrings__DefaultConnection Server=...;Database=GCCDatabase;... REQUIRED
SMTP Settings SmtpSettings__* Host, Username, Password OPTIONAL
Azure AD B2C AzureAdB2C__* ClientId, TenantId, Secret OPTIONAL

Configuration Methods

Method A: AccuWeb Control Panel

Most Secure ✓

  1. Log into AccuWeb control panel
  2. Navigate to your application
  3. Go to Application Settings
  4. Add environment variables

Method B: web.config

Server-Side Configuration

<environmentVariables> <environmentVariable name="GCC_JWT_SECRET" value="your-secret-here" /> </environmentVariables>

Method C: appsettings.Production.json

Pre-Deployment Edit

Edit before publishing. Less secure for credentials.

SQL Server Connection String Format

Server=your-server.database.windows.net; Database=GCCDatabase; User Id=your_username; Password=your_secure_password; Encrypt=True; TrustServerCertificate=False; MultipleActiveResultSets=true;
⚠ JWT Secret Generation: Use a cryptographically secure random generator for your JWT secret. Minimum 64 characters required. The current production secret has been set and is secure.

5 Performance & Load Handling

⚠ AccuWeb Load Concerns: Shared hosting environments like AccuWeb have resource limitations. This section addresses your concerns about API request handling capacity.

Built-In Performance Features

✓ Response Caching

Certificate tile data cached in memory. Reduces database queries by 80%.

✓ API Rate Limiting

Prevents abuse. Configured: 60/min, 1000/hour for APIs.

✓ Database Connection Pooling

Reuses database connections efficiently.

✓ Async/Await Pattern

Non-blocking I/O throughout application.

✓ ReadyToRun Compilation

Faster startup and improved performance.

✓ Static File Compression

Gzip compression for CSS/JS reduces bandwidth.

Expected Load Capacity

Scenario Requests/Second Concurrent Users Notes
Typical Shared Hosting 10-30 req/sec 50-100 users Adequate for small to medium traffic
With Caching Enabled 50-100 req/sec 200-300 users Cached responses served faster
API-Only Traffic 20-40 req/sec 100-150 users Limited by rate limiting (1000/hour)
Database-Heavy Operations 5-15 req/sec 20-50 users CREATE/UPDATE operations

AccuWeb Resource Recommendations

Minimum Plan Requirements

  • RAM: 2GB minimum, 4GB recommended
  • CPU: Shared vCPU (2+ cores)
  • Bandwidth: 50GB/month minimum
  • Storage: 10GB for app + database

Recommended Upgrades

  • VPS or Dedicated Server for high traffic
  • Separate SQL Server instance
  • CDN for static files (wwwroot)
  • Redis cache for distributed caching

Performance Optimization Strategies

1. Enable Output Caching (Already Configured)

// Certificate tiles cached for 5 minutes services.AddMemoryCache(); services.AddResponseCaching();

2. Database Query Optimization

  • All certificate queries use indexes
  • Eager loading prevents N+1 queries
  • Pagination limits result sets
  • Connection pooling enabled by default

3. Monitor Application Performance

Use the built-in /health endpoint to monitor:

  • Database connectivity
  • Memory usage
  • Response times
  • Active connections

Rate Limiting Configuration (Production)

Endpoint Pattern Limit Period Purpose
*/api/* 60 requests 1 minute Prevent abuse
*/api/* 1000 requests 1 hour Hourly quota
*/api/* 5000 requests 1 day Daily quota
*/api/*/auth/login 5 requests 1 minute Brute force protection
💡 Scaling Beyond AccuWeb: If you experience performance issues, consider:
  • Upgrading to AccuWeb VPS or Dedicated Server
  • Moving to Azure App Service (auto-scaling)
  • Using Azure SQL Database (better performance than shared SQL)
  • Implementing Azure Redis Cache for distributed caching
  • Using Azure CDN for static content delivery

7 Troubleshooting

Application Won't Start

  1. Check logs\stdout_*.log
  2. Verify .NET 8.0 Runtime installed
  3. Check Application Pool is started
  4. Verify web.config configuration
  5. Check Windows Event Viewer

Database Connection Errors

  1. Verify connection string format
  2. Check SQL Server firewall rules
  3. Test connection from server
  4. Verify database user permissions
  5. Check encryption settings

500 Internal Server Error

  1. Temporarily enable detailed errors
  2. Check application logs
  3. Verify all DLLs uploaded
  4. Check file permissions
  5. Review web.config syntax

Static Files Not Loading

  1. Verify wwwroot folder uploaded
  2. Check IIS static content enabled
  3. Verify file permissions
  4. Check browser console for errors
  5. Clear browser cache

Performance Issues

  1. Check /health endpoint for metrics
  2. Review database query performance
  3. Check memory usage in IIS
  4. Verify caching is enabled
  5. Consider AccuWeb plan upgrade

High API Traffic / Rate Limiting

  1. Review rate limiting configuration
  2. Monitor API usage patterns
  3. Implement caching for frequent requests
  4. Consider API key quotas
  5. Upgrade hosting plan if needed

Enable Detailed Error Messages (Temporary)

⚠ Security Warning: Only enable detailed errors temporarily for debugging. Disable immediately after troubleshooting.
<!-- In web.config, add to environmentVariables --> <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Development" />

JWT secret is unique, random, and 64+ characters

HTTPS is enforced (HTTP redirects to HTTPS)
Security headers present in responses
Swagger endpoint disabled (/swagger returns 404)
Detailed error messages disabled in production
Rate limiting configured and active
SQL Server connection uses encryption
Sensitive file extensions blocked (.db, .config, .log)
Production environment variable set correctly
