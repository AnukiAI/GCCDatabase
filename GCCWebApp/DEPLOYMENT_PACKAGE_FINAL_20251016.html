Database Detection Logic - How It Works

The application detects which database provider to use based on the connection string format in Program.cs (lines 45-124).

SQL Server Detection Criteria

if (connectionString.Contains("Server=tcp:") || (connectionString.Contains("Server=") && ( connectionString.Contains("database.windows.net") || connectionString.Contains("mssqllocaldb") || connectionString.Contains("sqlexpress") || connectionString.Contains("Integrated Security") || connectionString.Contains("Trusted_Connection") || (connectionString.Contains("Database=") && connectionString.Contains("TrustServerCertificate")))) { // Use SQL Server builder.Services.AddDbContext<ApplicationDbContext>(options => options.UseSqlServer(connectionString)); Console.WriteLine("Using SQL Server database provider"); } else { // Default to SQLite Console.WriteLine("Using default SQLite database provider"); }
Production Connection String (Fixed):
Server=tcp:68.71.129.120,1533;Database=gccwebap_certificates;User Id=GCC_adminxyz123;Password=Q3Ez4e!gE_47KNi;Encrypt=True;TrustServerCertificate=True;MultipleActiveResultSets=true;

The Server=tcp: prefix ensures the connection string matches the first condition in Program.cs, guaranteeing SQL Server detection.
Why October 11 Package Failed:
Connection string format Server=68.71.129.120,1533;... (without "tcp:") did not match the old detection logic. The code looked for "mssqllocaldb", "sqlexpress", or other keywords that weren't present.

Minimal Configuration for AccuWebHosting

The web.config has been simplified to remove features not available on AccuWebHosting:

<?xml version="1.0" encoding="utf-8"?> <configuration> <location path="." inheritInChildApplications="false"> <system.webServer> <handlers> <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreModuleV2" resourceType="Unspecified" /> </handlers> <aspNetCore processPath=".\GCCWebApp.exe" arguments="" stdoutLogEnabled="true" stdoutLogFile=".\logs\stdout" hostingModel="inprocess"> <environmentVariables> <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" /> <environmentVariable name="DatabaseProvider" value="SqlServer" /> <environmentVariable name="USE_SQL_SERVER" value="true" /> </environmentVariables> </aspNetCore> </system.webServer> </location> </configuration>

Key Configuration Points

  • processPath=".\GCCWebApp.exe" - Self-contained executable
  • arguments="" - EMPTY (critical for self-contained deployment)
  • stdoutLogEnabled="true" - Enables application logging to logs folder
  • hostingModel="inprocess" - Runs inside IIS worker process for better performance
  • Environment variables explicitly set for SQL Server

Removed Sections (Not Available on AccuWebHosting)

  • URL Rewrite: IIS URL Rewrite Module not installed
  • Security Headers: Can be added later if module becomes available
  • Request Filtering: Simplified for initial deployment

Troubleshooting Guide

HTTP 500.30 - App Failed to Start

Symptoms: All requests return HTTP 500.30 error.

Possible Causes:
  • Missing .NET runtime files (check GCCWebApp.exe exists and is correct size)
  • Corrupted package extraction
  • Wrong web.config arguments (should be empty for self-contained)
Solution:
  1. Check stdout logs in httpdocs/logs/ for error details
  2. Verify GCCWebApp.exe exists and is ~136 KB
  3. Verify web.config has arguments="" (empty)
  4. Re-extract package or re-upload

HTTP 500.19 - Cannot Read web.config

Symptoms: IIS returns HTTP 500.19 with win32 status 183.

Cause: Invalid web.config or missing IIS module.

Solution: This should NOT occur with the minimal web.config in this package. If it does:
  • Verify web.config file is not corrupted
  • Check IIS has ASP.NET Core Module V2 installed
  • Contact AccuWebHosting support

"Using default SQLite database provider"

Symptoms: Stdout log shows "Using default SQLite database provider" followed by SQL Server connection errors.

Cause: Connection string not detected as SQL Server format.

Solution: This should NOT occur with this package. If it does:
  1. Verify appsettings.Production.json has connection string starting with Server=tcp:
  2. Check ASPNETCORE_ENVIRONMENT is set to "Production" in web.config
  3. Verify package is from October 16 build (not October 11)

Database Connection Errors

Symptoms: App starts but cannot connect to SQL Server.

Possible Causes:
  • SQL Server not accessible from AccuWebHosting (firewall)
  • Wrong database credentials
  • Database name incorrect
Solution:
  1. Verify SQL Server connection from AccuWebHosting server: telnet 68.71.129.120 1533
  2. Check stdout logs for specific SQL Server error message
  3. Verify credentials: Username=GCC_adminxyz123, Database=gccwebap_certificates
  4. Contact database administrator to verify firewall rules
