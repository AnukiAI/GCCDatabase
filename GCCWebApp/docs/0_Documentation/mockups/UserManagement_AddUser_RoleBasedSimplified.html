Add User - Role-Based Simplified Approach

Option D: Role selection automatically determines what data access configuration is needed

Simplification Principle

  • Admin/Analyst: Full system access - no data restrictions needed
  • Partner: Show ONLY Partner selector (Amazon/Novi) - they see all certificates tagged with that partner
  • External Client: Show ONLY Company selector - they see only their companies' products
  • API Integration: Show Partner OR Company based on integration type
  • Public: Read-only access to public certificates - no configuration needed

Key Simplification

This approach eliminates the confusion of "both Partner AND Company".
Each role type gets ONLY the association that makes sense for their access pattern:

  • Partner employees → Partner selection only
  • Company representatives → Company selection only
  • Internal staff → No selection needed (full access)

Questions for Client Clarification

1. Is there ever a case where a Partner user needs Company selection?

Example: An Amazon employee who only needs to see specific companies' Amazon-tagged certificates (not ALL Amazon certificates)?

2. Is there ever a case where an External Client needs Partner selection?

Example: A company rep who needs to see their company's certificates PLUS all certificates tagged with Amazon?

3. What about companies that ARE Amazon partners?

If Acme Corp is an Amazon partner, should an Acme rep see: (a) Only Acme's products, (b) Acme's products + all Amazon-tagged certs, or (c) Something else?

4. Should the Partner entity be linked to Companies in the database?

Currently, Partner and Company are separate. If they were linked (Company belongs to Partner), would that simplify the model?
