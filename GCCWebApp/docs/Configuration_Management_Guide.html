2. Database Setup Procedures

2.1 Method 1: Using Entity Framework Migrations (Recommended for Production)

Step 1: Create empty database
sqlcmd -S ANUKI01 -E -Q "CREATE DATABASE GCCDatabase_Dev;"
Step 2: Apply migrations
dotnet ef database update
Known Issue: Early migrations contain SQLite-specific code and may fail on SQL Server with cascade delete errors.

Error Message: "Introducing FOREIGN KEY constraint 'FK_Certificates_Users_UpdatedBy' on table 'Certificates' may cause cycles or multiple cascade paths."

2.2 Method 2: Using EnsureCreated (Development Only)

Step 1: Set environment to Development
set ASPNETCORE_ENVIRONMENT=Development
Step 2: Run application (will auto-create schema)
dotnet run --urls "http://localhost:5101"

The application will call SeedData.InitializeAsync() which uses EnsureCreatedAsync() to create the schema.

Note: EnsureCreatedAsync() bypasses migrations and creates schema directly from the model. This is NOT recommended for production.

2.3 Troubleshooting: SQL Server Cascade Delete Issue

If you encounter cascade delete errors, you need to modify the foreign key configurations in ApplicationDbContext.cs:

// In OnModelCreating method, update Certificate foreign keys: modelBuilder.Entity<Certificate>() .HasOne(c => c.CreatedByUser) .WithMany() .HasForeignKey(c => c.CreatedBy) .OnDelete(DeleteBehavior.SetNull); // Change from Cascade to SetNull modelBuilder.Entity<Certificate>() .HasOne(c => c.UpdatedByUser) .WithMany() .HasForeignKey(c => c.UpdatedBy) .OnDelete(DeleteBehavior.SetNull); // Change from Cascade to SetNull

3. Configuration Management Strategy

3.1 Environment-Specific Settings

Environment File Used Database Behavior Seeding
Development appsettings.Development.json EnsureCreated + Seed test data Full test dataset
Testing appsettings.Test.json EnsureCreated (InMemory) Minimal test data
Staging appsettings.Staging.json Apply Migrations Essential data only
Production appsettings.Production.json Apply Migrations No seeding

3.2 Configuration Precedence Order

ASP.NET Core loads configuration in the following order (later sources override earlier ones):

  1. appsettings.json
  2. appsettings.{Environment}.json
  3. User Secrets (Development only)
  4. Environment Variables
  5. Command Line Arguments
Best Practice: Store sensitive data (passwords, API keys) in environment variables or Azure Key Vault, not in configuration files.

5. Common Configuration Issues

5.1 Database Provider Not Detected

Symptom: Application uses SQLite instead of SQL Server
Solution: Ensure connection string contains one of the detection keywords: Integrated Security, Trusted_Connection, or TrustServerCertificate

5.2 Migration Cascade Delete Errors

Symptom: "may cause cycles or multiple cascade paths"
Solution: Change OnDelete(DeleteBehavior.Cascade) to OnDelete(DeleteBehavior.SetNull) for User foreign keys

5.3 Connection String Not Found

Symptom: "DefaultConnection" not found
Solution: Verify appsettings.{Environment}.json contains ConnectionStrings section and matches current environment
