Overview

The GCC Database Solution implements three distinct Single Certificate View pages, each tailored to different user types with role-appropriate data visibility and functionality.

Key Principle: Each view type shows different levels of detail based on the user's role and relationship to the certificate. This ensures data privacy while maximizing transparency for authorized users.

Purpose

Single Certificate Views provide detailed information about individual certificates, allowing users to:

  • View comprehensive certificate details
  • Download certificate PDFs
  • Access product identifiers (ASIN, UPC, GTIN, EAN)
  • Verify certification authenticity
  • Edit/manage certificates (Internal users only)

The Three View Types

Public View

Audience: Anonymous public users

Purpose: Certificate verification and public transparency

No Authentication

External View

Audience: Partner users (Amazon, Wayfair)

Purpose: Enhanced details for partner integration

External Role Required

Internal View

Audience: GCC Analysts and Admins

Purpose: Full certificate management and editing

Analyst/Admin Only

Technical Implementation

Controller Actions

Three separate controller actions handle the different views:

1. Public View - CertificateSingleView

/// Summary: Certificate single view by ID or certificate number - Public access allowed /// Route: GET /Certificate/CertificateSingleView/{id} [AllowAnonymous] public async Task<IActionResult> CertificateSingleView(string id) { // Lookup certificate by ID or certificate number if (int.TryParse(id, out int certificateId)) certificate = await _certificateRepository.GetByIdAsync(certificateId); else certificate = await _certificateRepository.GetCertificateByNumberAsync(id); var model = new CertificateDetailsViewModelSimple { Certificate = certificate, CanEdit = false, CanDelete = false, ShowInternalData = false }; return View(model); }

2. External View - CertificateExternalView

/// Summary: Certificate external view - For external partners /// Route: GET /Certificate/CertificateExternalView/{id} [Authorize(Policy = "ExternalAccess")] public async Task<IActionResult> CertificateExternalView(string id) { // Same certificate lookup logic var model = new CertificateDetailsViewModelSimple { Certificate = certificate, CanEdit = false, CanDelete = false, ShowInternalData = false }; return View(model); }

3. Internal View - CertificateInternalView

/// Summary: Certificate internal view - Only for Admin and Analyst roles /// Route: GET /Certificate/CertificateInternalView/{id} [Authorize(Policy = "AnalystOrAdmin")] public async Task<IActionResult> CertificateInternalView(string id) { // Same certificate lookup logic var model = new CertificateDetailsViewModelSimple { Certificate = certificate, CanEdit = CanUserEditCertificate(), CanDelete = CanUserDeleteCertificate(), ShowInternalData = true }; return View(model); }

View Models

All three views use the same CertificateDetailsViewModelSimple model:

public class CertificateDetailsViewModelSimple { public Certificate Certificate { get; set; } public bool CanEdit { get; set; } public bool CanDelete { get; set; } public bool ShowInternalData { get; set; } }

View Files

  • Public: Views/Certificate/CertificateSingleView.cshtml
  • External: Views/Certificate/CertificateExternalView.cshtml
  • Internal: Views/Certificate/CertificateInternalView.cshtml
Note: The views use conditional rendering based on the ShowInternalData flag to show/hide internal-only fields. This allows for maintainable code while supporting role-specific visibility.

Data Access

Certificate Lookup

All three views support flexible certificate lookup by either:

  • Database ID: Integer value (e.g., 55, 124)
  • Certificate Number: Formatted string (e.g., "24-0366", "25-1234")
// Try to parse as integer first (ID) if (int.TryParse(id, out int certificateId)) { certificate = await _certificateRepository.GetByIdAsync(certificateId); } else { // Find by certificate number certificate = await _certificateRepository.GetCertificateByNumberAsync(id); }

Related Data Loading

The repository automatically loads related entities:

  • Company (with contact information)
  • Product (with product type)
  • Certification Type
  • Product IDs (ASIN, UPC, GTIN, EAN collections)
  • Tags (External and Internal)
  • Custom Field Values

Tile View to Single View Navigation

Each Tile View has corresponding JavaScript that handles navigation to the appropriate Single View:

CertificateTileViewExternal certificate-tile-view-external.js /Certificate/CertificateExternalView/{id}
CertificateTileViewInternal certificate-tile-view-internal.js /Certificate/CertificateInternalView/{id}

JavaScript Functions

The JavaScript files implement two key navigation functions:

Internal View Example (certificate-tile-view-internal.js)

// Navigate to certificate detail (same window) window.viewCertificateDetails = function(id) { if (!id) { console.error('Certificate ID is missing'); showToast('Error: Certificate ID not found', 'error'); return; } window.location.href = `/Certificate/CertificateInternalView/${id}`; }; // Open certificate in new tab function viewCertificate(id) { window.open(`/Certificate/CertificateInternalView/${id}`, '_blank'); }

External View Example (certificate-tile-view-external.js)

// Navigate to certificate detail (same window) window.viewCertificateDetails = function(id) { if (!id) { console.error('Certificate ID is missing'); showToast('Error: Certificate ID not found', 'error'); return; } window.location.href = `/Certificate/CertificateExternalView/${id}`; }; // Open certificate in new tab function viewCertificate(id) { window.open(`/Certificate/CertificateExternalView/${id}`, '_blank'); }
Important: Each JavaScript file MUST use the correct Single View URL that matches the user's role. Using the wrong URL will result in either authentication errors or displaying inappropriate data visibility.

Navigation Flow

Users can reach Single Views from:

  • Tile Views: Clicking on a certificate tile navigates to the appropriate Single View
  • Direct URLs: Bookmarked or shared URLs for specific certificates
  • Search Results: Certificate search results link to Single Views
  • Dashboard: Recent certificates widget links to Internal View
  • Edit Pages: After saving, redirects to appropriate Single View

Troubleshooting Common Issues

Issue #1: 404 Not Found When Clicking Certificate Tiles

Symptom: Clicking on certificate tiles results in "404 Not Found" error

Root Cause

JavaScript files are using incorrect URL patterns that don't match the actual controller action names.

Common Incorrect URLs:

  • /Certificate/CertificateSingleViewInternal/{id} ❌ (does not exist)
  • /Certificate/CertificateSingleViewExternal/{id} ❌ (does not exist)

Correct URLs:

  • /Certificate/CertificateInternalView/{id} ✅
  • /Certificate/CertificateExternalView/{id} ✅
  • /Certificate/CertificateSingleView/{id} ✅ (public only)

Solution

Fix Applied (October 6, 2025):

// File: wwwroot/js/certificate-tile-view-internal.js // BEFORE (incorrect): window.location.href = `/Certificate/CertificateSingleViewInternal/${id}`; // AFTER (correct): window.location.href = `/Certificate/CertificateInternalView/${id}`;
// File: wwwroot/js/certificate-tile-view-external.js // BEFORE (incorrect - was using public view): window.location.href = `/Certificate/CertificateSingleView/${id}`; // AFTER (correct - now uses external view): window.location.href = `/Certificate/CertificateExternalView/${id}`;

Verification Steps

  1. Clear browser cache (Ctrl+F5 or Cmd+Shift+R)
  2. Navigate to tile view page
  3. Click on a certificate tile
  4. Verify it navigates to the correct Single View page without 404 error
  5. Check browser Developer Tools Console for any JavaScript errors

Issue #2: Wrong Data Visibility in Single View

Symptom: External users see internal-only data, or internal users see limited data

Root Cause

User is being directed to the wrong Single View action for their role.

Solution

Ensure the Tile View JavaScript calls the correct Single View URL:

User Role Must Use This URL JavaScript File
Public (Anonymous) /Certificate/CertificateSingleView/{id} certificate-tile-view.js
External Partners /Certificate/CertificateExternalView/{id} certificate-tile-view-external.js
Analyst/Admin /Certificate/CertificateInternalView/{id} certificate-tile-view-internal.js

Issue #3: Authorization/Authentication Errors

Symptom: "Access Denied" or "401 Unauthorized" when accessing Single Views

Possible Causes

  • User not logged in when accessing Internal or External views
  • User has wrong role assignment
  • Authorization policy not configured correctly

Solution Steps

  1. Verify user is logged in (check authentication cookie)
  2. Check user role assignment in database
  3. Verify authorization policies are registered in Startup.cs/Program.cs
  4. Test with test credentials:
    • Admin: admin@greencirclecertified.com / Admin123!
    • Analyst: analyst@greencirclecertified.com / Analyst123!
    • External: partner@amazon.com / Partner123!

Issue #4: Certificate Not Found (404)

Symptom: "Certificate {id} not found" error message

Possible Causes

  • Certificate ID doesn't exist in database
  • Certificate number format is incorrect
  • Database connection issue

Debugging Steps

  1. Check application logs for certificate lookup errors
  2. Verify certificate exists in database:
    SELECT * FROM Certificates WHERE Id = {id}
  3. Test with known certificate ID from Tile View
  4. Ensure related entities (Company, Product, CertificationType) are not null
