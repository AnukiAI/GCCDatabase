6. Troubleshooting

6.1 Common Issues

Issue: Login failed for user 'GCC_DevUser'
Cause: SQL Server authentication might not be enabled (Mixed Mode)
Solution: Verify LoginMode = 2 (Mixed Mode)
-- Check authentication mode (should return 2) EXEC xp_instance_regread @rootkey = 'HKEY_LOCAL_MACHINE', @key = 'Software\Microsoft\MSSQLServer\MSSQLServer', @value_name = 'LoginMode';
Issue: Cannot connect with sqlcmd using SQL authentication
Note: This is expected if TCP/IP is not enabled
Solution: .NET application can still connect using Shared Memory/Named Pipes
The application connection is what matters, not sqlcmd connectivity
Issue: Password contains special characters causing connection errors
Solution: Ensure password is properly quoted in connection strings
Current password (DevP@ss2024!SQL) is tested and working

6.2 Verification Steps

  1. Verify SQL login exists and is enabled
  2. Check database user exists with proper permissions
  3. Test .NET application connection (most important)
  4. Verify data integrity after connection

7. Security Best Practices

7.1 Password Management

Important Security Guidelines:
  • Never commit passwords to source control
  • Use different passwords for each environment
  • Use Azure Key Vault or environment variables for production
  • Rotate passwords regularly
  • Use strong passwords (12+ characters, mixed case, numbers, symbols)
