2. System Overview

2.1 System Architecture

High-Level Architecture

The GCC Database Solution follows a modern three-tier architecture pattern:

  • Presentation Layer: ASP.NET Core MVC views with Bootstrap 5 for responsive UI, jQuery for dynamic interactions
  • Business Logic Layer: Service layer implementing domain logic, workflow management, and business rules
  • Data Access Layer: Entity Framework Core 9.0 with repository pattern for database abstraction

Key Architectural Decisions

Decision Rationale Trade-offs
ASP.NET Core MVC Enterprise-grade framework with excellent tooling, Microsoft support, and .NET ecosystem + Mature ecosystem, strong security
- Higher hosting costs than PHP/Node
SQL Server Robust relational database with ACID compliance, excellent for audit trails + Reliable, feature-rich, great tooling
- Licensing costs vs. open-source
Azure AD B2C Enterprise SSO with MFA, reduces password management burden + Secure, scalable, MFA built-in
- Added complexity vs. simple auth
RESTful API Industry standard for system integration, well-understood by partners + Ubiquitous, easy to consume
- Less efficient than GraphQL for complex queries
Server-side rendering Better SEO for public certificate pages, simpler architecture than SPA + SEO-friendly, progressive enhancement
- Less dynamic than React/Vue

US-001: Certificate Creation

Priority: CRITICAL | Complexity: MEDIUM | Sprint: 1-2
✓ COMPLETE
As an Admin or Analyst
I want to create new certificates with all required fields and validations
So that I can issue official GCC certifications to companies
Business Value: Enables digitization of certificate issuance process, reducing manual errors and processing time from 2-4 hours to 15-30 minutes per certificate. Critical path functionality for entire system.

    • CreatedAt timestamp set to server UTC time

    • Certificate image upload (PNG/JPG, max 5MB)
    • Product IDs (ASINs, UPCs, GTINs - multiple supported)
    • Internal tags (for internal classification)
    • External tags (visible to partners and public)
    • Location and Country information
  5. Success Feedback:
    • Success toast notification displayed on save
    • Redirect to certificate details page
    • Certificate appears in search results immediately

US-004: Certificate Lifecycle Management (14-State Workflow)

Priority: CRITICAL | Complexity: HIGH | Sprint: 4-5
✓ COMPLETE
As an Admin or Analyst
I want to manage certificate status transitions through a defined workflow
So that certificates follow proper approval processes and compliance requirements
Business Value: Ensures regulatory compliance, provides clear audit trail for certifications, and prevents unauthorized status changes. Critical for maintaining certification integrity and meeting audit requirements.
14-State Workflow Definition:
Draft
→
ApplicationSubmitted
→
UnderReview
→
TechnicalReview


↓

ComplianceVerification
→
FinalApproval
→
Active
→
ExpiringSoon


↓

RenewalInProgress
→
Active (renewed)
Expired
Archived
Cancelled
ClientDeclined
Detailed Acceptance Criteria:
  1. Status Transition Rules:
    • Each status has defined "allowed next states" configuration
    • Invalid transitions blocked with clear error messages
    • Role-based restrictions (e.g., only Admin can move to Archived)
    • Automated transitions: Active → ExpiringSoon (30 days before expiration)
    • Automated transitions: ExpiringSoon → Expired (on expiration date)
  2. Status History Tracking:
    • Every status change logged in CertificateStatusHistory table
    • History includes: OldStatus, NewStatus, ChangedBy, ChangedAt, Reason (optional)
    • History viewable in certificate details page
    • Cannot be edited or deleted (immutable audit trail)
  3. Email Notifications:
    • Notification sent on key status changes (ApplicationSubmitted, Active, Expired)
    • Recipients: Certificate creator, company contact email
    • Email template includes certificate details and next steps
  4. Automated Expiration Checking:
    • Daily background job checks for expiring certificates
    • Runs at 2:00 AM server time
    • Updates Active → ExpiringSoon (30 days before)
    • Updates ExpiringSoon → Expired (on expiration date)
    • Job execution logged in system logs
Implementation Details:
Service: Services/CertificateWorkflowService.cs - TransitionStatusAsync() method
Model: Models/CertificateStatus.cs - Enum with 14 states
Background Job: Services/CertificateExpirationJob.cs - Hosted service for automation
Database: CertificateStatusHistory table with foreign key to Certificates
Email: Services/EmailService.cs - SendStatusChangeNotification() method
Dependencies:
  • Certificate Management (US-001) - Base certificate data
  • Email Service - Notification delivery
  • Background Job Scheduler - Automated expiration checks
