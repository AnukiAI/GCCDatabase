1. Project Overview

Vision Statement

Build a comprehensive certificate management system for Green Circle Certified (GCC) that enables efficient certificate lifecycle management, partner integration, and public certificate verification.

Key Business Objectives

  • Certificate Management: Complete lifecycle from application to expiration with 14-state workflow
  • Partner Integration: Dedicated support for Amazon, Wayfair, and other strategic partners
  • Public Access: Public-facing certificate verification database with advanced search capabilities
  • Reporting: Comprehensive analytics dashboard with 12 statistical cards and 5 data tables
  • Security: Enterprise-grade role-based access control with Azure AD B2C integration

User Roles & Permissions

Role Access Level Key Capabilities
Admin Full System Access User management, all certificate operations, system configuration
Analyst Extended Access Certificate management, reporting, no user management
External Partner Access Limited to partner certificates, filtered data views
Internal GCC Staff Extended viewing permissions, internal tags access
Public Read-Only Public certificate data viewing only

Database Schema Highlights

Certificate Table (Primary Entity)

CREATE TABLE Certificates (
    Id INT PRIMARY KEY IDENTITY,
    Number VARCHAR(50) UNIQUE NOT NULL,
    Status VARCHAR(50) NOT NULL,
    Partner VARCHAR(100),
    CompanyId INT FOREIGN KEY REFERENCES Companies(Id),
    ProductId INT FOREIGN KEY REFERENCES Products(Id),
    CertificationType VARCHAR(100) NOT NULL,
    EffectiveDate DATE NOT NULL,
    ExpirationDate DATE NOT NULL,
    CertificateImagePath VARCHAR(500),
    CreatedBy VARCHAR(100) NOT NULL,
    CreatedAt DATETIME NOT NULL,
    UpdatedBy VARCHAR(100),
    UpdatedAt DATETIME,
    CONSTRAINT CK_Certificate_Dates CHECK (ExpirationDate > EffectiveDate)
)

Key Relationships

  • Certificate → Company: Many-to-One (required)
  • Certificate → Product: Many-to-One (required)
  • Certificate → CertificateProductIds: One-to-Many (ASINs, UPCs, etc.)
  • Certificate → User: CreatedBy/UpdatedBy audit fields
  • User → Role: Many-to-Many via UserRoles table
  • User → Company: Many-to-Many (External user filtering)
  • User → Partner: Many-to-Many (External user filtering)

API Specifications

Authentication Methods

  • JWT Token: Bearer token in Authorization header for user authentication
  • API Key: X-API-Key header for system-to-system integration
  • Cookie: Session cookie for web application authentication

Security Requirements

Authentication & Authorization

  • Primary: Azure AD B2C with multi-factor authentication (email/SMS)
  • Fallback: Cookie-based authentication with secure session management
  • Session Timeout: 30 minutes of inactivity
  • Password Policy: Minimum 8 characters, uppercase, lowercase, number, special character
  • Role-Based Access: 5 distinct roles with policy-based authorization
  • API Security: JWT tokens with 1-hour expiration, refresh token support

Data Protection

  • Transport Security: HTTPS only with TLS 1.2+ enforced
  • Input Validation: Server-side validation on all user inputs
  • SQL Injection Prevention: Parameterized queries via Entity Framework
  • XSS Protection: Output encoding, Content Security Policy headers
  • CSRF Protection: Anti-forgery tokens on all POST/PUT/DELETE operations
  • Rate Limiting: 60 requests/minute per user, 1000/hour, 5000/day
  • File Upload Security: MIME type validation, size limits, virus scanning ready
