1. Quick Start

Three steps to get your first data:

1 Get your API key from GCC (format: gcc_partner_[hash])

2 Make your first request:

curl -X GET "https://[production-domain]/api/v1/certificates/gs1" \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Accept: application/json"

3 You'll receive a JSON response with all Active certificates tagged to your partner account, including ASINs, certification details, and PDF download links.

Integration model: You PULL data from GCC. GCC does not push to you. Call the API on your schedule to retrieve current certification data.

2. Authentication

Every request requires the X-API-Key header:

X-API-Key: gcc_partner_b451fb3b31c645e9dd900c3c7b2f6250fbb7480bbb4510d602efc5e52102fc4d
Response CodeMeaningAction
200SuccessProcess the response
401Invalid or missing API keyCheck your key in the header
403Endpoint not permittedContact GCC support
404Resource not foundVerify certificate number or product ID
429Rate limit exceededWait and retry (200 requests/hour)
500Server errorContact GCC support with request details

3. API Endpoints

Base URL: https://[production-domain]/api/v1

GET /certificates/gs1 RECOMMENDED

List all certificates in GS1 JSON-LD format. ASINs and product IDs are always included.

Parameters: pageNumber (default: 1), pageSize (default/max: 100), searchTerm, sortBy

GET /certificates/gs1/{certNumber}

Get a single certificate by number in GS1 format.

Example: /certificates/gs1/24-0366

GET /certificates

List all certificates in standard JSON format.

Parameters: pageNumber, pageSize, searchTerm, sortBy, includeProductIds (boolean - set to true to include ASINs)

GET /certificates/number/{certNumber}

Get a single certificate by number in standard JSON format.

GET /certificates/search/productid

Find a certificate by ASIN, UPC, or GTIN.

Parameters: productId (required), type (ASIN, UPC, GTIN, EAN)

Example: /certificates/search/productid?productId=B08XQRT456&type=ASIN

GET /certificates/{certNumber}/download

Download the certificate PDF document. Returns application/pdf.

6. Error Handling

All errors return a consistent JSON structure:

{
  "success": false,
  "error": "Description of what went wrong"
}
CodeErrorResolution
401Missing or invalid API keyEnsure X-API-Key header is present with a valid key
403Insufficient permissionsYour key may not have access to this endpoint
404Certificate or product ID not foundVerify the certificate number or ASIN exists and is Active
429Rate limit exceededDefault: 200 requests/hour. Wait and retry with exponential backoff.
500Server errorContact GCC support with the request details

7. Pagination

List endpoints return max 100 records per page. Use the pagination object to iterate:

// Page 1
GET /api/v1/certificates?pageNumber=1&pageSize=100

// Check response
"pagination": {
  "totalCount": 250,
  "pageNumber": 1,
  "pageSize": 100,
  "totalPages": 3,
  "hasNext": true,      // ← more pages available
  "hasPrevious": false
}

// Page 2
GET /api/v1/certificates?pageNumber=2&pageSize=100

Loop until hasNext is false.

8. Security & Access Scope

ControlDetails
TransportHTTPS/TLS required for all requests
AuthenticationAPI key via X-API-Key header
Data IsolationYour key only returns certificates where Partner = "Amazon". No other partner data is accessible.
Status FilterOnly Active certificates are returned. Draft, expired, suspended, and revoked certs are excluded.
Rate Limiting200 requests/hour (configurable per key)
Key ManagementKeys issued and revocable by GCC administrators
You will never see: other partner data, internal notes, workflow history, draft certificates, or GCC user information.
