**The controls are the point.** Two earlier runs of this script "passed" their denial assertions

### Carry forward — NOT blocking this upload

- **F1 → now `DEF-433`, a CUTOVER BLOCKER.** HIGH at public cutover, MEDIUM today — the two new routes are anonymous, unthrottled and
  serialise on a blocking lock.** `FileUploadService.cs:519` takes a process-wide
  `SemaphoreSlim(1,1)` with **synchronous `Wait()` and no timeout**, called from the `[AllowAnonymous]`
  `CertificatePageCount` action. Every `IpRateLimiting` rule in `appsettings.Production.json` is
  scoped to `*/api/*`, and these are MVC routes — **independently confirmed: the five configured
  endpoints are all `*/api/*`, so nothing throttles them.** Concurrent anonymous requests would block
  thread-pool threads faster than they are injected, taking down the whole site, not just previews.
  **Today's only protection is `TestEnvironmentGate:Enabled = true`** — verified live: gccwebapp.com
  302s to `/__gate`. **This must be fixed before that gate is ever turned off.** Minimum: rate-limit
  rules for the two routes, `WaitAsync(timeout)` instead of `Wait()`, and stop opening the same PDF
  three times per page turn.
- **F4 → now `DEF-432`. DECISION 2026-09-18: ship as-is, fix in the next build** (Shawn: *"ship
  as-is, fix F4 next build"*). LOW — `CertificatePageCount` omits the DEF-310 revalidation headers** its two siblings set.
  The JSON leaves with no `Cache-Control`/`private`, and the same URL returns `{"pages":N}` to the
  owner and 404 to everyone else — exactly the role-dependent response DEF-310 exists to stop a
  shared cache storing. One line; harmless until something is put in front of Plesk.
- **F3 → folded into `DEF-433` as required fix #4.** LOW — no test asserts the "not yet effective" window on the new routes.** The gate itself is
  correct (effective-date is checked before any file is touched), but no assertion covers it, so a
  later "simplification" would not fire a test. The X-SENSE fixture (`26-0441`/`26-0442`, effective
  2026-10-21) is the one that can prove it, and only until that date.
- **F5 · INFO — `page=-1` returns 200 and the thumbnail** rather than 404, because the branch tests
  `page > 0`. Nothing reaches the PDF library. Inconsistent contract, not a defect.

## What was NOT checked — stated so it is not mistaken for a cleared gate

- **Gates 1, 2, 3, 5 and 6 were not run.** They are the judgment gates: UI/design-guide compliance,
  cross-role and responsive regression, data-scoping review, traceability audit, performance. The
  mechanical evidence overlapping them is strong — 4B proves cross-surface product-ID parity, the
  DEF-430 suite drives both tile views including an External-scoped session, and DEF-431 is 19/19
  output-identical including the external view as a scoped user — but that is **overlap, not
  substitution**. If one item deserves a formal UI/scoping review before the client sees it, it is
  **CR-053**: it renders PDF pages on demand on a shared host.
- **Gate 6 has no trustworthy number from this machine.** A cold-plan A/B produced 2.83s and then
  142.99s for the *same* control query, whose SQL is byte-identical in both builds. Wall-clock here
  measures contention, not the application. Logical reads are the usable metric (DEF-431), and by
  that measure nothing in this bundle regressed.
- **CR-053 was verified by the session that built it, not independently re-run here.** 14/14 with a
  named harness and screenshots is good evidence; it is not evidence this session gathered.
- **The marker harness had a real bug, found and fixed during this cut.** `marker-check-20260918.py`
  initially reported CR-051 and CR-052 markers ABSENT from a bundle that demonstrably contains them:
  Razor view markup is stored in the DLL as **UTF-16LE**, and the harness compared UTF-8 bytes — four
  false FAILs. The standing `verify-bundle.py` already handles both encodings (line 166) and was
  never affected. Fixed, and both control markers pass — but it is a reminder that a marker check
  which cannot see view markup would silently pass every view-only change.
