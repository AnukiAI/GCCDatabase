## The one real difference: `migrations/` is in this zip and was not in 1200

`Scripts/deploy.ps1` generated an idempotent EF script and the hygiene gate flagged it:

> `[WARN] full-history script (38 migrations). SQL Server compiles every block before its guard can
> skip it, so a block referencing a dropped column will abort the run. Prefer -FromMigration <target
> high-water>.`

**Do not run `migrations/apply-migrations.sql` against the test database.** Gate 7 on the 1200 cut
established that **every migration in the repo is already applied on the target** — the newest is
`20260908175939_CR045_CertificationResultsVerbatimSort` and it is on the server. Running a
full-history script buys nothing and carries the DEF-386 abort risk (the generator had to repair 3
`EXEC(CONCAT(...))` statements in this very run). The zip's own printed "Next steps" include a
migration step; that step does not apply to this deploy.

If a migrations folder in the bundle is unwanted, re-cut with
`-FromMigration 20260908175939_CR045_CertificationResultsVerbatimSort` and the script comes out empty.
