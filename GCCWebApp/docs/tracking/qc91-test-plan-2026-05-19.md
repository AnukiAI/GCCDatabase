## TC-QC91-A — Edit Product preserves Name, Type, Subcategory across save

**Symptom under test:** Carly 5/11: *"When I went back into 25-8760 it keeps clearing out Product Name and Product Type even after saving edit."* Maps to DEF-138 (Sku/Model null-wipe causing the second-line `SKU: N/A` to read as cleared) and DEF-134 (editProduct() did not pre-fill dropdowns).

**Steps:**
1. Login as `analyst` at `http://localhost:5101/Account/Login`.
2. Navigate to `/Product/Management`.
3. Find any product with a non-null `Sku`, `ProductTypeId`, `ProductSubcategoryId` in the table — capture its name and the SKU sub-line.
4. Click the row's edit icon (pencil).
5. **Assert (pre-fill):** Company, Category, Product Type, Subcategory dropdowns all pre-populated with the saved values. Name field populated with the product's name.
6. Without changing any field, click **Save Product**.
7. Wait for the success toast.
8. **Assert (table render):** The row's first line still shows the original Product Name. The `SKU: ...` second line still shows the original SKU (NOT `SKU: N/A`).
9. Click the same row's edit icon again.
10. **Assert (round-trip):** All 5 dropdowns + Name + Description still hold the original values.

**Pass criteria:** Steps 5, 8, 10 hold. Name never blanks. SKU sub-line never flips to N/A. Type and Subcategory persist visually.

**Linked code:** `Controllers/ProductController.cs:408-409` (DEF-138 null guard), `Views/Product/Management.cshtml:849-878` (DEF-134 pre-fill).

## TC-QC91-B — Add Product persists Type/Subcategory into the list

**Symptom under test:** Carly 5/1: *"There was no product type and subcat filled in from list. So I added to 25-8760 and 25-8777. But they then are not showing in list at all."* Maps to DEF-134 (FK was pointed at empty `ProductSubcategories` table; save threw FK violation; user saw a generic error).

**Steps:**
1. Login as `analyst`, navigate to `/Product/Management`.
2. Click **Add New Product**.
3. Fill: Product Name = `QC91-SIT-{timestamp}`, Company = any, Category = pick a category that has Types (e.g. Chemicals).
4. **Assert (cascade A):** Product Type dropdown populates after picking Category. Wait ≤ 1s.
5. Pick a Product Type (e.g. Plastics).
6. **Assert (cascade B):** Subcategory dropdown populates (e.g. HDPE, LDPE...).
7. Pick a Subcategory.
8. Click **Save Product**.
9. **Assert (toast):** Green success toast. No red "Error saving product" toast.
10. **Assert (list render):** New row appears with the chosen Type and Subcategory in the dedicated columns. SKU sub-line under the Name shows `SKU: N/A` (expected — modal does not collect SKU per QC #92).

**Pass criteria:** Save succeeds, no error toast, row renders with Type + Subcategory populated.

**Linked code:** DEF-134 FK retarget migration `20260504204044_RetargetProductSubcategoryFkToProductTypes`. DEF-136 false-error-toast fix (`saveProduct` post-save path no longer calls broken `showNotification`).

## TC-QC91-C — Sort arrows do not overlap column header text

**Symptom under test:** Carly 4/3: *"Columns are added but the sort arrows are overlapping text. See image 39."* Class conflict between `.admin-sort-icon` (absolute-positioned) and `.sort-icon` (inline) on the same `<span>`. Fixed by `position: static; transform: none;` override in `product-management.css`.

**Steps:**
1. Login as `analyst`, navigate to `/Product/Management`.
2. Take a full-page screenshot at desktop viewport 1440×900.
3. Inspect each sortable column header: Product Name, Company, Category, Product Type, Subcategory, Status, Certs, IDs.
4. **Assert:** Each `▼` (or `▲` when active-sort) arrow renders *inline, to the right of* the header text — NOT stacked on top of it.
5. Click Product Type header.
6. **Assert:** Arrow flips to `▲`, list re-sorts ascending by Product Type. No visual overlap.
7. Click again.
8. **Assert:** Arrow flips to `▼`, list re-sorts descending. Still inline.

**Pass criteria:** Zero visual overlap in any header in default state, ascending state, or descending state.

**Linked code:** `wwwroot/css/product-management.css` `#product-table th .sort-icon` rule with `position: static; transform: none;`. JS sort handler at `Views/Product/Management.cshtml:812-837`.

## TC-QC91-D — Certificate-edit "Add New Product" modal shows all categories

**Symptom under test:** Carly 5/11: *"When I try editing cert and adding a new product it won't let me access all the Product Categories. See image."* Code path: `wwwroot/js/certificate-inline-create.js:240-248` reads category options from the page's `#ProductCategoryId` `<select>` which is populated from `_context.ProductCategories.Where(pc => pc.IsActive)`.

**Steps:**
1. Login as `analyst`, navigate to `/Certificate/Index`.
2. Open any existing certificate for edit, or click **Add Certificate**.
3. Pick a Company.
4. In the **Product Name** dropdown, type a product name that does not exist (e.g. `QC91-D-{timestamp}`).
5. Click the **"Add as new product"** suggestion that appears.
6. **Assert (modal opens):** Quick-add Product modal renders with Name pre-filled.
7. Open the **Product Category** dropdown in the modal.
8. Capture the dropdown option count.
9. **Assert (parity):** Count matches the option count on the parent page's `#ProductCategoryId` dropdown.
10. **Cross-check vs DB:** Open SSMS, run `SELECT COUNT(*) FROM ProductCategories WHERE IsActive = 1`. Count should match step 8.

**Pass criteria:** Modal's Product Category dropdown has the same number of options as the cert page's dropdown AND the DB's active-category count.

**If fail:** The "missing categories" symptom is real. Two possible causes — (i) JS at `certificate-inline-create.js:240-248` is losing options, (ii) the parent select has been visually filtered by SearchableSelect at the moment of modal open. Investigate further.

**If pass + count is just small (e.g. 3-4):** Carly's complaint was that the LIST is small, not that it's missing items. That's a data state — would need a CR to add more `ProductCategories` rows.
