| **Pending deploy 2026-07-01** (code-only, no migration; **fold into the next rebuild**) | **DEF-301 — Company names with an apostrophe (e.g. `Gemma's Company Co.`, `O'Brien`) failed to load in the certificate views.** Filtering the tile views by a company whose name contains an apostrophe showed "Failed to load certificates" and no tiles. Root cause was server-side, **not** a client encoding bug: the SQL-injection guard in `SecurityHeadersMiddleware` inspected the still-URL-encoded query string and treated a bare `%27` (encoded `'`) / `%22` (encoded `"`) as an attack signature, so any legitimate apostrophe/quote in a company filter, search term, or autocomplete returned **HTTP 400 "Bad request"**. Fix: the guard now decodes the query string before matching and keys off the meaningful injection combinations (`' or `, `'; drop`, `'--`, `union select`, …) instead of blanket-blocking encoded punctuation — ordinary apostrophes pass, real payloads stay blocked. Affects all three tile views + autocomplete (one shared middleware). Code-only, **no migration**. Verified on localhost:5101 (2026-07-01): apostrophe company filter and `O'Brien` search now return **HTTP 200** (were 400); real injection `x' OR '1'='1` and `union select … from users` still return **400**. Single-file change (`Middleware/SecurityHeadersMiddleware.cs`). See defect register DEF-301. **Note:** any existing prod certs with apostrophe company names are affected today and resolve the moment this ships. |
