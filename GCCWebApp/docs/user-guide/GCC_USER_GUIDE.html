  1. Appendix — Glossary

1. About this guide

This guide explains how to use the GreenCircle Certified (GCC) Database — the web application at greencirclecertified.com/database — to manage product certifications, supplier relationships, and partner integrations.

The guide is organized two ways so you can use whichever fits the moment:

  • Workflow-driven. Each section starts with "How to do X" — the steps you take from start to finish for a common task (upload a certificate, approve one, share with a partner, run an export).
  • Field-reference appendix. Every form field is listed in a table with its purpose, whether it's required, and any validation rules. Use this when you just need to look up "what does this field mean?"
Heads-up

What you see on screen depends on your role. If a section in this guide describes a button or field you can't see, your account probably doesn't have permission for it. Contact your administrator if you think that's wrong.

2. Who uses the platform

Users fall into two broad camps — internal (GCC staff who run the certification program) and external (everyone else who consumes the data). Each camp has two sub-roles:

Admin Analyst External Partner (API) Public

2.1 Internal users — GCC staff

Admin

Administrators

Full access to every screen — user management, role assignment, system settings, tag and product-type administration, partner API key management, and all certificate operations.

Analyst

Analysts (day-to-day operators)

The certificate workflow operators. Can create, edit, approve, and transition certificates through the workflow. Can manage companies, products, and identifiers. Cannot manage users, roles, or system-level settings.

2.2 External users — your clients and partners

External users are the people and systems outside GCC that consume certificate data. There are two sub-types:

External

Company users (manufacturers / suppliers)

Real people who sign in to the web app to view their own company's certificates. Read-only, scoped to the company associated with their account. Can view, filter, search, and export their certificates. Cannot create or edit, and never see internal-only data (such as internal tags or analyst notes). The role is named External on the User Management page.

Partner (API)

Partner integrations (machine-to-machine, e.g. Amazon)

Not a web user — partners consume certificate data through the Partner API using a long-lived API key. Partners see only their own scope, and only certificates in approved/published states. Documented separately in the Partner API Developer Guide.

Heads-up on terminology

You'll see "external" used two ways in this guide. Lowercase — "external user" — is the umbrella that covers both Company users and Partners. Capitalized as a role badge — External — it refers specifically to the Company-user role (which is what the User Management page calls it).

2.3 Public — anonymous visitors

Not a "role" so much as a state: anyone who lands on the site without signing in. Public visitors can browse the certificate tile view (§9) but only see certs in the publicly-visible statuses — Client Approved – Paid and Republished. They cannot see internal tags, drafts, expired certs, or anything on hold. The Public badge appears on sections that public visitors can use.

3. Getting started — signing in

Admin Analyst External

Open https://greencirclecertified.com/database in any modern browser (Chrome, Edge, Firefox, Safari). You'll land on the public certificate tile view — anyone can browse public certificates without signing in.

To do anything else (create, edit, see internal data, or view supplier-scoped data), click Sign In in the top-right.

  • Admin / Analyst: sign in with your GCC-issued credentials.
  • Company user (External role): sign in with the credentials your GCC administrator provisioned for you.
  • Partner: Partners don't sign in to the web app — they integrate via the Partner API using an API key. See §27.
  • Forgot password: use the Forgot password? link on the sign-in page.
Test environment

If the site shows a yellow "TEST" banner along the top, you are on the pre-launch staging environment — anything you do here is for testing and may be wiped before launch. Production uses the same URL but without the banner.

4. Uploading a certificate

4.1 Who can do this

Admin Analyst

Only Admin and Analyst users can upload new certificates. External users — both Company users and Partners — cannot create certificates; they consume the certificates that Analysts have already created and approved.

4.2 Quick steps

If you've done this before and just need the sequence:

  1. Open the upload page From the Certificate Management screen, click Add Certificate in the top-right.
  2. Pick the company Selecting a company auto-fills the company's email, website, and the list of available products.
  3. Fill in the required fields Certification Type, Product, Effective Date, Expiration Date, Status. Fields marked with a red asterisk (*) are required.
  4. Upload the certificate PDF Drag a PDF onto the upload zone or click to browse. The first page is auto-converted to a preview image.
  5. Add product identifiers (optional) ASINs, UPCs, GTINs, etc. Especially important for Amazon partner certificates.
  6. Save Click Save, or Save & Add Another if you're uploading several in a row.

4.3 Detailed walkthrough

Step 1 — Open the upload page

From the main menu, go to Certificates → Certificate Management. In the top-right of that page, click Add Certificate. You'll arrive at the Create Certificate form.

The form is divided into four sections, top to bottom:

  • Certificate Information — the main metadata: company, product, dates, status, etc.
  • Certificate PDF Document — the actual PDF file.
  • Product Identifiers — ASINs, UPCs, GTINs, model numbers — anything that uniquely identifies the product on a retailer or distributor system.
  • Additional Fields — extra fields specific to the certification type you chose (these appear dynamically once you pick a type).

Step 2 — Pick the company

Start typing in the Company dropdown — it's searchable. When you pick a company:

  • Company Email and Company URL are auto-filled from the company record.
  • The Product Name dropdown loads with just that company's products. If you change either email or URL on this form, the change writes back to the company record.
  • If the company you need doesn't exist yet, use the + Add New option at the bottom of the dropdown to create it inline.
Tip

Inline-creating a company or product saves a trip to the Admin screens. The new record is created with sensible defaults — you can always go back and fill in details later from Company / Product Management.

Step 3 — Certification # is automatic

The Certification # field is read-only and shows a preview number. The final number is assigned at the moment of save. If another analyst saves a certificate at the exact same time, you'll be given the next available number automatically — you don't need to do anything.

Step 4 — Certification type and subcategories

Pick a parent Certification Type (e.g., USDA Organic, ECOCERT, B-Corp). Once you do:

  • The Certificate Subcategories dropdown populates with any sub-types under that parent. Pick as many as apply — they appear as removable pills below the field.
  • The Additional Fields section at the bottom of the form may populate with extra fields specific to that certification type. These are configured per type by an Administrator on the Certification Types admin page.

Step 5 — Product and product hierarchy

Pick the Product Name from the list loaded for the chosen company. The Product Category, Product Type, and Product Subcategory below it will auto-fill from the product's stored hierarchy. You can override any of them, or leave them blank if the product isn't yet categorized.

Step 6 — Dates and status

  • Effective Date — when the certificate becomes valid.
  • Expiration Date — when it stops being valid. The system uses this to auto-expire certificates when the date passes.
  • Status — for a brand-new cert, leave this on Draft (the default). The certificate moves through the 8-state workflow afterwards via the dedicated workflow controls on the certificate detail page (see §8).

Step 7 — Partner, certification results, pathway

  • Partner — if this certificate is being supplied to a specific partner (e.g., Amazon), pick them here. Leave as None for general certifications.
  • Certification Results — optional free-text field for a numeric score, threshold value, or pass/fail note that the partner needs to see (e.g., Amazon may require a percentage value). Up to 1,000 characters.
  • Pathway — applies only to Amazon Climate Pledge Friendly (CPF) certifications. Pick the CPF pathway the cert qualifies under, or leave blank.

Step 8 — Location and country

Where the certification was issued or where the certified facility is located. Free text for city/state, picker for country.

Step 9 — Tags (sidebar)

On the right side of the form:

  • External Tags — visible to everyone, including external users (Company users in the web app and Partners via the API). Use these for tags you want everyone to see.
  • Internal Tags — only visible to Admin and Analyst users. Use these for classification that shouldn't leak to clients or partners.

Step 10 — Upload the PDF

In the Certificate PDF Document section, drag a PDF onto the upload zone or click it to open a file picker. Constraints:

  • File must be PDF format.
  • Maximum size 10 MB.
  • The first page is automatically converted to a JPEG preview image, which is what appears in the tile views and on the certificate detail page.

Step 11 — Product identifiers

In the Product Identifiers section, click + Add to attach one or more identifiers. For each one, pick the type (ASIN, UPC, GTIN, EAN, ISBN, MPN, or SKU) and enter the value. You can also tag each identifier with its partner and a free-text description.

Amazon note

For Amazon certificates, ASIN is the identifier Amazon uses. SKU is included when known but isn't always available — that's expected.

Step 12 — Save

At the bottom of the form, you have four buttons:

  • Save — saves the certificate and takes you to the certificate detail page.
  • Save & Add Another — saves and returns you to a fresh blank form. Use this when uploading several certs in a row for the same company.
  • Cancel — returns to the Certificate Management list without saving.
  • Reset Form — clears every field on this form (does not navigate away).

On success, you'll see a green toast notification in the bottom-right.

4.5 Tips & common questions

The company I need isn't in the dropdown.

Type the name into the dropdown — at the bottom of the search results, there's a + Add New option. Clicking it opens a small dialog to create the company without leaving the upload form.

The product I need isn't in the dropdown.

Same pattern as company — pick the company first, then if the product isn't listed, use + Add New in the product dropdown to create it. The new product will be attached to the currently-selected company.

The PDF upload says "file too large."

The 10 MB ceiling is a hard limit. If your PDF is larger, re-export it from the source with image compression enabled, or use an online "compress PDF" tool, then try again. The visual fidelity needed for the preview image is modest.

I saved a certificate but the wrong number was assigned.

You can't change the number after save. If a real mistake (e.g., wrong company), the right path is to set the certificate to a non-public status and create a corrected one. Contact your administrator before deleting — deleted records are not easily recoverable.

What's the difference between Internal and External tags?

External tags are visible everywhere — to external users (Company users in the web app and Partners via the API). Use them for tags that classify the certificate publicly. Internal tags are only seen by Admin and Analyst users. They never leave GCC. Use them for internal-only classifications like priority, review status, or who-owns-this.

What if I need to upload 50 certificates at once?

Don't use this form — use the bulk Import page instead (covered in §5 of this guide, coming in v1.1). Import accepts a CSV plus a zip of PDFs and creates many certificates in one operation.

Why is "Status" defaulted to Draft? Can I change it?

Draft is the default starting state in the 8-state certificate workflow (see §8) — it lets you save partial work without it appearing in public/partner views. You can pick a different initial status here (e.g., if you're uploading an already-approved cert from a previous system), but the normal flow is: save as Draft, review, then advance through the workflow on the detail page.

5. Editing a certificate

Admin Analyst

5.1 Where to start

From the Certificate Management list (or any tile view in internal mode), click any certificate to open its detail page. In the top-right of the detail page, click Edit Certificate. The form is identical in layout to the upload form (§4) — same sections, same fields — pre-filled with the certificate's current values.

5.2 What's different from upload

  • Certification # is already assigned and remains read-only.
  • PDF upload is optional — the existing PDF stays in place unless you upload a replacement.
  • Status changes here follow the same workflow rules as the dedicated transition controls (see §8). You cannot make an invalid transition (e.g., jump from Draft to Republished).
  • Product Identifier rows that already exist are editable in-place; their Status is read-only because it follows the parent certificate's status automatically.
  • If the cert is in a public status (Client Approved – Paid, Republished), edits go live immediately on save — to Company users in the web app and to Partners via the API. You'll see a green toast confirming the save.
Be careful

Editing a publicly-visible certificate is immediate. If you need to take it out of view first, move it to Hold, edit, then move it back. Hold removes the cert from both the public tile view and the Partner API.

5.3 Field reference

See §4.4 — every field on the Edit form is identical to the Create form, with the exceptions noted in §5.2 above.

5.4 Tips & common questions

I need to replace the PDF with a corrected version.

On the Edit page, simply upload the new PDF in the same way you would on Create — drag & drop or click to browse. On save, the new PDF replaces the old one and the preview image is regenerated.

Can I change the Certification # of an existing cert?

No. Certification numbers are permanent once assigned. If a real correction is needed, contact your administrator — the safest path is usually to set the wrong-numbered cert to a non-public status and create a corrected one with the right metadata.

I changed the company on an existing cert. Did the product update?

Yes — the Product Name dropdown reloads when you change the Company, just like on the Create form. You'll need to pick a product that belongs to the new company before you can save.

6. Bulk-importing certificates

Admin Analyst

Bulk import is the right tool when you have more than a handful of certificates to load at once — for example, when on-boarding a new partner, migrating historical certs, or processing a monthly batch from a supplier.

6.1 Quick steps

  1. Download the import template From Certificate Management, click Template in the top-right toolbar. This downloads a blank CSV with the correct header row.
  2. Fill in the template One row per certificate. PDF filename column references a file by name; the file itself goes in the companion zip.
  3. Zip your PDFs Create a single .zip containing all the PDF files referenced in your CSV. Filenames must match exactly (case-sensitive on some systems).
  4. Open the Import dialog From Certificate Management, click Import. Choose the CSV and the zip together.
  5. Review the preview The system parses the CSV and shows a row-by-row preview with any validation warnings highlighted. Resolve issues in your CSV and re-upload, or proceed with valid rows only.
  6. Apply Click Apply Import to create the certificates. A progress bar shows how many rows have been processed. A summary at the end lists which rows succeeded and which failed.

6.3 Tips & common questions

An import row failed because the company didn't exist.

Bulk import does not create companies or products on the fly — they must exist before the import runs. The cleanest order is: (1) bulk-create or verify companies, (2) bulk-create or verify products, (3) bulk-create certificates. See §12 and §13 for company/product imports.

The preview shows everything as Draft even though my CSV says Paid.

Double-check the exact spelling — the value must match the display name, e.g., Client Approved - Paid with the hyphens and exact casing. Anything that doesn't match a valid status name falls back to Draft.

What if a PDF in the zip is missing or doesn't match a row?

Missing PDFs cause the corresponding row to fail validation. Extra PDFs in the zip that no row references are ignored without error. The preview screen flags missing files row-by-row.

Can I re-import to update existing certificates?

No — bulk import only creates new certificates. To bulk-update existing certs, contact your administrator; updates of business records require a formal change request.

8. The 8-state certificate workflow

Admin Analyst

Every certificate has a status that controls who can see it and what can be done with it. The platform has eight statuses, and movement between them is governed by business rules — you can't jump from any state to any other state.

8.1 The eight statuses

StatusVisibilityMeaning
DraftInternal onlyJust created or being edited. Not yet approved. Default for new certs.
Client Approved – Not PaidInternal onlyGCC has approved the certification but the client hasn't paid for publication yet. Not visible publicly.
Client Approved – ConfidentialInternal onlyApproved and paid, but the client has asked for it to remain confidential. Counted in internal "active" stats but not shown publicly or via the Partner API.
Client Approved – PaidPublicLive — visible on the public tile view and returned by the Partner API. The primary "active" state.
HoldInternal onlyTemporarily removed from public view. Use when re-issuing a corrected PDF or when a client has requested a pause.
ExpiredInternal onlyPast its expiration date. The system can auto-move certs to Expired when their expiration date passes.
RepublishedPublicWas Expired and has been re-issued. Equivalent to Client Approved – Paid for visibility purposes.
Expired – No Annual VerificationInternal onlyFinal state for certs that expired and were not renewed with the annual verification. Cannot be transitioned anywhere except back to Draft.

8.2 Allowed transitions

From each starting status, you can move only to specific next statuses:

FromAllowed next statuses
DraftClient Approved – Not Paid · Client Approved – Confidential · Client Approved – Paid · Hold
Client Approved – Not PaidClient Approved – Paid · Client Approved – Confidential · Hold · Expired
Client Approved – ConfidentialClient Approved – Paid · Hold · Expired
Client Approved – PaidHold · Expired · Republished · Expired – No Annual Verification
HoldDraft · Client Approved – Not Paid · Client Approved – Confidential · Client Approved – Paid
ExpiredRepublished · Draft
RepublishedExpired · Expired – No Annual Verification · Hold
Expired – No Annual VerificationDraft (only)

8.3 How to change a status

  1. Open the certificate detail page.
  2. In the action toolbar, click Change Status.
  3. The dropdown only shows valid next statuses for the current state.
  4. Pick one and confirm. The change is immediate and logged in the audit history.

8.4 Auto-expiration

The system runs a background check daily. Any certificate whose Expiration Date has passed and which is in a publicly-visible state (Paid or Republished) is automatically moved to Expired. The audit history records this as a system change.

8.5 Tips & common questions

I tried to move a cert from Draft to Republished and it wasn't an option.

You can't — that's not a valid transition. Republished only comes from Expired. To make a brand-new cert live, the path is Draft → one of the Client Approved variants.

What if I need to temporarily hide a cert from public/partner view?

Use Hold. It removes the cert from the public tile view and the Partner API, but keeps it visible to Admin/Analyst. Move it back to Client Approved – Paid when ready.

Why are there three "Client Approved" variants?

To distinguish billing/publication state from approval state. Not Paid means GCC has signed off but the client hasn't paid yet — no public visibility. Confidential means the client has paid but specifically asked for the cert not to be shown publicly. Paid is the normal published state.

  • Public tile view — anyone (signed in or not) can see all certificates in Client Approved – Paid or Republished.
  • Internal tile view — Admin/Analyst sees every certificate regardless of status, plus internal-only fields and bulk actions.

Every filter, search, and sort you apply updates the URL in the address bar. Copy the URL and send it to a colleague — when they open it, they'll see the same filtered view (subject to their role permissions). This is the easiest way to share, for example, "all Amazon-tagged certs expiring this month."

9.4 Tips & common questions

The search isn't finding a cert I know exists.

Public users only see certs in Paid or Republished status. If you're not signed in, certs in Draft / Hold / Expired won't appear. Sign in as Admin/Analyst to see everything.

I want to send a colleague a link to "all expired certs."

Apply the filter, then copy the URL from the address bar. The URL contains your current filter state.

The filter sidebar is hiding the content on my tablet.

On screens ≤ 1024 px the sidebar collapses by default. Click Show Filters at the top of the list to open it.

10. Company-user tile view

External

This section covers the tile view as it appears for Company users — the people from manufacturers and suppliers who sign in to see their own organization's certificates. (Partners — the other type of external user — don't use the web UI; they consume data via the API. See §27.)

The Company-user tile view is a tailored variant of the main tile view (§9), automatically scoped to the user's company. The differences from the public view:

  • Only certificates whose Company matches the signed-in user's company are shown.
  • Internal tags are hidden everywhere — list, detail, exports.
  • No Add Certificate button. Company users cannot create certificates.
  • No Edit or Delete actions on detail pages.
  • No Actions column on related views (e.g., Product Management).
  • Otherwise the search, filters, sort, infinite scroll, and CSV export work the same way.

10.1 What a Company user can do

  • Browse, search, and filter their company's certificates.
  • Open detail pages and download PDFs.
  • Export their visible list to CSV.
  • Edit their own account profile (name, email, password).
For administrators

When provisioning a Company user (the External role in User Management), you must associate the account with a Company on the User Management page (§17). Without that association, the user will see an empty list.

11. Exporting to CSV

Admin Analyst External

Every list view in the platform — Certificates, Companies, Products, Users, Tags, Roles, Partners — has an Export button in the top-right toolbar. CSV is the only export format (no Excel, JSON, or PDF) — this is a deliberate standard so the file is universally importable.

11.1 How export works

  • The export reflects the currently-filtered view. If you have search and filters active, only matching rows are exported.
  • The file is downloaded immediately — no email, no background job.
  • The filename includes the date you exported (e.g., certificates_2026-05-21.csv).
  • Company users' exports only contain rows their account is scoped to.

11.2 Tips & common questions

The export only has a few rows but the list shows many more.

Active filters are applied to the export. Clear filters first if you want everything.

Can I get a JSON or Excel export?

No — by policy, exports are CSV only. Most spreadsheet apps (Excel, Google Sheets, Numbers) open CSVs natively and can save them as Excel from there if needed.

The exported CSV looks garbled when I open it in Excel.

This usually means a character-encoding mismatch. Open the CSV using Data → Get External Data → From Text/CSV in Excel and choose UTF-8 encoding. (Modern Excel versions handle this automatically.)

12. Company Management

Admin Analyst

Companies are the suppliers/manufacturers whose products you're certifying. Every certificate is attached to a company. Manage them at Companies → Management.

12.1 What you can do

  • Search by name, email, or URL.
  • Add New Company opens a modal with name / email / URL fields.
  • Edit a row inline (or via the actions menu) — same three fields.
  • Import / Template / Export for bulk operations (CSV).

12.2 Field reference

FieldRequired?Notes
Company NameYesMust be unique. Up to 200 characters.
EmailOptionalPrimary contact email. Up to 255 characters. Validated as email format.
URLOptionalCompany website. Up to 500 characters. Must start with http:// or https://.

12.3 Tips

I can't delete a company.

Companies that have certificates or products attached cannot be deleted — that would orphan the related records. Either move the related records to a different company first, or keep the company record for historical reference.

I changed a company's email here but it didn't show on the certificate.

The certificate's company email is auto-populated at creation time. On the cert Edit form, edits to the company email there write back to the company record. From this Company Management page, changes flow forward — future certs will pick up the new email automatically.

13. Product Management

Admin Analyst

Products are the items being certified. Every product is owned by exactly one Company, and every certificate references exactly one Product. Manage them at Products → Management.

13.1 What's on the page

  • Table of all products with Company, Product Name, Category, Product Type, Subcategory, Certificate count, and Identifier count columns.
  • Search across all columns.
  • Sort by any column.
  • Pagination — 50 products per page.
  • Add New Product opens a modal.
  • Actions column lets you Edit or Deactivate a product.

13.2 Field reference

FieldRequired?Notes
CompanyYesThe company this product belongs to. Cannot be changed after creation.
Product NameYesHow the product appears throughout the platform.
Product CategoryOptionalTop level of the 3-level hierarchy (§14).
Product TypeOptionalMiddle level. Filtered by Category.
Product SubcategoryOptionalBottom level. Filtered by Type.

Note: Product Identifiers (ASIN, UPC, GTIN, etc.) are attached to individual certificates, not to products themselves. See §4 step 11.

13.3 Tips

Why can't I edit Status, SKU, or Model Number on the product form?

Those fields were removed per requirements — products are a simple Company + Name + 3-level hierarchy. Anything more specific (SKU, model, ASIN, etc.) lives on the certificate's Product Identifiers section, where it can vary per-certificate.

14. Product Types (3-level hierarchy)

Admin Analyst

Products are organized into a three-level hierarchy: Category → Type → Subcategory. Administrators define and maintain the hierarchy at Administration → Product Types.

14.1 The three levels

  • Category — broadest grouping (e.g., "Personal Care", "Food & Beverage").
  • Type — a kind of product within a Category (e.g., "Skincare" within Personal Care).
  • Subcategory — a specific class of Type (e.g., "Moisturizers" within Skincare).

14.2 What you can do

  • Add a new node at any level.
  • Re-parent a node by editing its parent reference.
  • Rename a node — the change propagates to every product and certificate referencing it.
  • Delete a node — only if it has no products attached.

14.3 Tips

I added a root-level category but everything shows up under "Chemicals and Raw Materials."

This was a known bug fixed in March 2026 — new root categories are now created correctly. If you still see this, contact your administrator.

I renamed a category — will old certificates show the new name?

Yes — the certificate references the category by ID, not name. Renaming updates the display everywhere.

15. Searching by product identifier

Admin Analyst External Public

If you have an ASIN, UPC, GTIN, or other identifier and want to know which certificate(s) it's attached to, drop it into the search box on the certificate tile view (§9). The search matches against all identifier values across all certificates.

Partners can also do this via the API:

  • GET /api/v1/certificates/search?productId=B07XYZ1234
  • Returns every certificate that has this identifier attached, with full details.
  • See the Partner API Developer Guide for the full request/response shape.

  3. Pick the role Admin, Analyst, External, or Partner. The role controls what the user can see and do (see §18).

17.4 Tips

I get "Failed to create user."

Most often this means the email is already in use. Errors now include the specific reason — check the toast notification text. If unclear, contact your administrator.

How do I delete a user?

Use Deactivate instead of delete. Deactivated users cannot sign in, but their historical audit-trail entries remain intact. The platform's default admin account cannot be deactivated or deleted.

An External user logged in but sees nothing.

Check that the user's Company is set on their profile. Without a Company, the External user's filtered view returns zero certs.

18. Role Management

Admin

Roles define what a user can see and do. Find them at Administration → Role Management.

18.1 The standard roles

Two are internal (GCC staff) and two are external (clients and partners). See §2 for the broader context.

18.2 Adding or editing a role

Click Add New Role or the Edit action on any non-system role. A role has:

  • Description — internal label, shown next to the name on the User form.

Caveat

Not every permission flag is enforced by code today. The standard roles (Admin/Analyst/External/Partner) are gated by role name throughout the application. Custom roles can be created but their effect is currently limited — consult your administrator before relying on a custom role.

19. Tag Management

Admin

Tags are labels you attach to certificates for ad-hoc classification. Two parallel taxonomies are maintained: External tags (visible to everyone) and Internal tags (visible only to Admin/Analyst). Manage them at Administration → Tags.

19.1 What you can do

  • Add / edit / delete individual tags.
  • Filter the list by tag type (External / Internal).
  • Import & export tags via CSV.

19.2 Field reference

FieldRequired?Notes
Tag NameYesMust be unique within its type. Up to 100 characters.
Tag TypeYesExternal (everyone sees it) or Internal (Admin/Analyst only). Cannot be changed after creation.
DescriptionOptionalFree text up to 500 chars. Shown as a tooltip when hovering a tag pill.

19.3 Tips

I deleted a tag — what happens to certificates that used it?

The tag is removed from every certificate that referenced it. The certificate itself is unaffected.

Can I convert an External tag to Internal?

No — the tag type is fixed at creation. If you need a tag with the opposite visibility, create a new tag and migrate the references.

20. Certification Types & custom fields

Admin

20.1 What you can do

  • Re-parent a subcategory to a different parent.

20.2 Custom fields

For each certification type, you can add extra fields the analyst will fill in when uploading. These fields appear in a single "Custom Fields" section on the cert form, on the cert detail page, and (if marked public) on the Partner API.

Field propertyNotes

20.3 Tips

I added a custom field to a type but it isn't appearing on existing certs.

Custom field values are stored per-certificate. Adding the field to the type makes it appear on the Create/Edit form for that type from that moment forward. Existing certs will show the new field as blank until you edit and fill it in.

21. Pathways (Amazon CPF)

23. Partner API Access — API keys

Admin

This is where you generate and manage the API keys that partners use to call the Partner API. Find it at Administration → Partner API Access.

23.1 The toolbar

  • Refresh — reloads the table.
  • Copy Docs Link — copies a shareable link to the Partner API Developer Guide for sending to the partner's engineering team.
  • API Docs — opens the live Swagger reference for the API.
  • Generate API Key — opens the key-generation flow.

23.2 Generating a key

  1. Click "Generate API Key" Modal opens.
  2. Pick the partner and a label The label is internal — call it something like "Amazon production" or "Amazon staging" so you can tell keys apart.
  3. Set an expiration (optional) Leave blank for no expiration, or pick a date. Keys can also be revoked manually any time.
  4. Generate & copy The key is displayed exactly once — copy it now and send it to the partner over a secure channel. After you close this modal, you can never see the key again (only revoke and regenerate).
Security

Treat API keys like passwords. Don't paste them into chat or email — use a password manager or another secure channel to deliver. If a key is ever exposed, revoke it immediately and issue a new one.

23.3 What partners do with the key

Partners include the key as an X-API-Key header on every API request. The full request/response reference, error codes, and integration examples live in the separate Partner API Developer Guide.

25. Forgotten password & reset

Admin Analyst External

If you can't remember your password:

  1. On the sign-in page, click Forgot password?
  2. Enter the email address on your account.
  3. You'll receive a reset link by email (check spam if it doesn't arrive within a minute or two).
  4. Click the link, enter a new password (minimum 8 characters with a mix of letters, numbers, and a symbol), and sign in.

If you're locked out and the reset email isn't arriving, contact your administrator. Admin can issue a new temporary password from the User Management page (§17).

26. Notifications & toasts

Admin Analyst External

The platform communicates success, warning, and error states using small "toast" notifications that pop up briefly in the bottom-right corner:

  • Green toast — success (e.g., "Certificate saved").
  • Yellow / orange toast — warning (e.g., "This will overwrite the existing PDF").
  • Red toast — error (e.g., "Failed to save — see details below").

Toasts auto-dismiss after a few seconds. Click anywhere on the toast to dismiss it early.

For irreversible actions (delete, deactivate, status transition to a final state), the platform shows a confirmation modal before performing the action — a single Yes/Cancel choice. Native browser confirms and alerts are intentionally not used.

27. Partner API quick reference

Admin Partner

This section is a brief overview for administrators provisioning partner access. The full developer reference (request/response shapes, error codes, sample code, integration patterns) lives in the separate GCC Database Partner API — Amazon Developer Guide distributed to partner engineering teams.

27.1 Base URL

https://greencirclecertified.com/database/api/v1

27.2 Authentication

Every request must include an X-API-Key header containing a key generated on the Partner API Access page (§23). Keys are long-lived but can be revoked at any time. There is no separate session or token exchange.

27.3 Main endpoints (partner-scoped)

EndpointPurpose
GET /certificatesList all certificates the calling partner is entitled to see (Paid + Republished, filtered to the partner).
GET /certificates/{id}Single certificate by internal ID.
GET /certificates/by-number/{n}Single certificate by certification number.
GET /certificates/search?productId=...Find certificates by attached product identifier (ASIN, UPC, etc.).
GET /certificates/gs1GS1-formatted variant used by certain partners' ingestion pipelines.
GET /certificates/{id}/pdfDownload the certificate PDF binary.

27.4 What partners see (and don't)

  • Only certs in Client Approved – Paid or Republished status.
  • Only certs scoped to the calling partner.
  • Status is always returned as "Active" (the internal lifecycle status names are not leaked).
  • Internal tags are never returned. External tags are.
  • Internal-only fields (analyst notes, audit history) are never returned.
For partner engineers

This guide is for administrators provisioning access. Partner engineering teams should work from the Partner API Developer Guide, which has the full schema, all error codes, and language-specific code samples.
