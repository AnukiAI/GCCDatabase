Reconciliation guide — why some numbers don't add up cleanly

Several reports look like they should compose into each other but don't. Each non-composition has a specific reason — none of them are bugs in the data, but the definitions diverge:

  1. "Next 3 Months" ACTION export vs the calendar-month badges.
  • Action button window: rolling [2026-05-26 .. 2026-08-26] (today through today+3 calendar months), future-only (ExpDate >= today).
  • "Expiring This Month" badge: calendar [2026-05-01 .. 2026-05-31] — includes dates earlier in the current month that have already passed.
  • "Expiring Next Month" badge: calendar [2026-06-01 .. 2026-06-30].
  • So Next3moAction ≠ ExpThisMonth + ExpNextMonth + ExpMonthAfter by design.
  1. "Expired Last Month" badge does NOT belong in any "Expiring" report.
  • "Expired Last Month" = certs whose date was in last month AND status is now Expired (already past).
  • Any "Expiring" report = future-facing only (date >= today). The 6 Expired-Last-Month certs are not in the Next 30 / Next 3 Months exports because their date is past.
  1. Top-N table totals (Companies, Product Types, Product Categories).
  • Visible "Total" on the table = sum of the top-N rows shown (capped at 10 or 5).
  • Export = ALL active certs (no top-N cap). So visible_sum ≤ export_rows is normal; equality only when fewer than the cap exist.
  • Specific to Product Types: most active certs don't have a Product Type assigned, so visible_sum is small (~4) while export = all 26 active certs. The export is showing the certs so you can see which ones are missing a Product Type, not just the top types.
  1. "# Certs by Status" table includes all 8 statuses including non-Active.
  • Sum of all 8 status counts = ALL certificates in the database (Draft + Hold + Expired + etc.), not just active.
  • That's why the visible total is larger than "Total Active Certs" — it's a different scope by design.
