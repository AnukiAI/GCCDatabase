1. Overview

This guide provides comprehensive step-by-step instructions for User Acceptance Testing (UAT) of the bulk import functionality across the GCC Web Application admin pages. The import feature enables administrators to efficiently upload CSV files to create or update multiple records simultaneously.

1.1 Purpose

The purpose of this document is to provide UAT testers with detailed guidance on testing the bulk import functionality, including test data, expected results, and defect reporting procedures.

1.2 Features Under Test

Feature Admin Page URL Path Priority
Company Import Company Management /Company/Index High
User Import User Management /Admin/UserManagement High
Tag Import Tag Management /Admin/Tags Medium
Product Import Product Management /Admin/ProductManagement High

1.3 Pre-Requisites

  • Valid Admin or Analyst login credentials
  • Access to test environment (localhost:5101 or production URL)
  • Test data CSV files (provided in TestData folder)
  • Modern web browser (Chrome, Edge, or Firefox recommended)

4. Test Execution Guide

4.1 Step-by-Step Import Process

1 Navigate to Admin Page

Login and navigate to the appropriate admin page:

  • Companies: Click "Companies" in navigation
  • Users: Admin → User Management
  • Tags: Admin → Tags
  • Products: Admin → Product Management
2 Initiate Import

Locate and click the Import button in the action toolbar (top-right area).

3 Select Test File

Navigate to the test data folder, select the appropriate CSV file, and click Open.

4 Review Import Preview

The Import Preview Modal will display with status indicators:

New Record will be created (does not exist)
Modified Record exists and will be updated
Unchanged Record exists and matches exactly
Error Validation failed - will not import
5 Execute Import

Review each row and click Apply Import to import valid rows, or Cancel to abort.

6 Verify Results

Confirm success notification appears and data grid refreshes with new records.

4.2 Verification Checklist

  • Row counts are correct
  • Status colors are appropriate
  • Error messages are clear and actionable
  • Preview data matches CSV content
  • Success notification appears after import
  • Data grid refreshes with new records
  • No duplicate records created

7. Defect Reporting

7.1 When to Log a Defect

Log a defect when any of the following occur:

  • Import succeeds but data is incorrect
  • Import fails for valid data
  • Invalid data imports without error
  • Error messages are unclear or missing
  • UI does not display correct status colors
  • Security test cases are not properly handled
  • Application crashes or shows unexpected behavior

9.3 Status Indicators Explained

NEW (Green)

Meaning: This record does not exist in the database and will be created.

Action: Click "Apply Import" to create this record.

Example: Importing a company named "New Corp" when no company with that name exists.

MODIFIED (Blue)

Meaning: A matching record exists but with different values. Import will update the existing record.

Action: Review the changes. Click "Apply Import" to update, or "Keep Current" to skip this row.

Example: Company "Acme Corp" exists with email "old@acme.com", CSV has "new@acme.com".

UNCHANGED (Gray)

Meaning: A matching record exists with identical values. No changes needed.

Action: This row will be skipped automatically. No action required.

Example: Company "Acme Corp" in CSV matches exactly what's in the database.

ERROR (Red)

Meaning: This row has validation errors and cannot be imported.

Action: Review the error message. Fix the CSV and re-import, or skip this row.

Example: Missing required field, invalid email format, or value exceeds max length.

"Name is required" Name field is empty Add a value to the Name column
"Invalid email format" Email doesn't match pattern Use format: user@domain.com
"Invalid URL format" URL missing protocol Start with http:// or https://
"Email already exists" Duplicate email in database Use a unique email address
"Invalid role" Role not Admin/Analyst/External Use exact case: Admin, Analyst, or External
"Type must be internal or external" Tag type invalid Use lowercase: internal or external
"Name exceeds maximum length" Value too long Shorten to within field limit

10. Help & FAQ

10.1 Frequently Asked Questions

Q: What file format is required for import?

A: CSV (Comma-Separated Values) files only. The first row must contain column headers that match the expected field names. Use the Template button to download a correctly formatted template.

Q: Can I import Excel files (.xlsx)?

A: No, Excel files are not supported. Save your Excel file as CSV first:
File → Save As → Select "CSV (Comma delimited)" → Save

Q: What happens if my CSV has extra columns?

A: Extra columns are ignored. Only columns matching the expected field names will be processed.

Q: How do I include a comma in a field value?

A: Wrap the entire value in double quotes. Example: "Smith & Jones, LLC"

Q: How do I include a quote character in a value?

A: Use two double quotes to escape. Example: "He said ""Hello""" becomes: He said "Hello"

Q: What encoding should my CSV file use?

A: UTF-8 encoding is recommended. This ensures special characters and international text display correctly.

Q: Can I undo an import?

A: No, imports cannot be automatically undone. However, you can manually edit or delete imported records. For large imports, consider testing with a small subset first.

Q: Why does my import show "Modified" when I expected "New"?

A: A record with a matching unique identifier (usually Name or Email) already exists. The import will update that record instead of creating a duplicate.
