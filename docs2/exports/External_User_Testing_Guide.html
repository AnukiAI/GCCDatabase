1. Overview — How Roles, Companies & Partners Work Together

The GCC Database uses a three-layer access control model to determine what data each user can see:

Layer 1: ROLE Layer 2: ASSOCIATION Layer 3: DATA SCOPE ──────────────── ────────────────────── ────────────────────── Admin/Analyst ─────────> No association needed ──────> ALL data (no filters) External ─────────> Assigned to Company(s) ────> Only that company's certificates & products Partner ─────────> Assigned to Partner(s) ────> Only certificates tagged with that partner program Public ─────────> No association needed ──────> Only publicly visible certificates (active status)
Critical Concept: Being authenticated is not enough. An External user with no company association sees zero data. A Partner user with no partner association sees zero data. The association is what unlocks their data scope.

This means two External users logged into the same application can see completely different data depending on which company they are associated with.

2. Data Model — How Users Connect to Data

2.1 External Users & Companies

External User (lisa.rodriguez) │ └──> Associated with: "Amazon" (Company) │ └──> Certificates where CompanyId = Amazon's ID └──> Products where CompanyId = Amazon's ID └──> Export: Only Amazon's data in CSV └──> Filters: Only Amazon-relevant options shown External User (david.kim) │ └──> Associated with: "Clover Imaging Group" (Company) │ └──> Certificates where CompanyId = Clover's ID └──> Products where CompanyId = Clover's ID └──> CANNOT see Amazon's certificates or products

How it works in the database:

  • Users have a many-to-many relationship with Companies (a user can be associated with multiple companies)
  • Every certificate has a required CompanyId field linking it to one company
  • Every product has an optional CompanyId field
  • When an External user loads the certificate view, the API query adds: WHERE CompanyId IN (user's company IDs)

2.2 Partner Users & Partner Programs

Partner User │ └──> Associated with: "Amazon" (Partner Program) │ └──> Certificates where Partner field = "Amazon" └──> This spans ALL companies that have Amazon-partnered certs └──> E.g., CertainTeed + Amazon cert, Kuiper + Amazon cert, etc.

Key difference from External:

  • External filtering is by Company — sees all certs for their company regardless of partner
  • Partner filtering is by Partner program name — sees all certs tagged with their partner across all companies

The three core partner programs are: Amazon, Novi, and Other.

2.3 Internal Users (Admin & Analyst)

Admin and Analyst users have no data filtering. They see all certificates, all products, all companies, all tags, and all data regardless of company or partner association. Their access is controlled only by role-level permissions (e.g., Analyst cannot delete certificates).

2.4 Public Users

Public users (and unauthenticated visitors on the public tile view) see only certificates with a publicly visible status (e.g., "Client Approved") that are not expired. No company or partner filtering applies — the filter is purely by certificate status.

4. What Each Role Cannot See or Do

External User Restrictions

Cannot See:

  • Certificates from other companies
  • Products from other companies
  • Internal tags on any certificate
  • Internal data fields on certificate details
  • Dashboard page
  • Administration menu or any admin page
  • Companies & Products submenu
  • Other companies in filter dropdowns

Cannot Do:

  • Add, edit, or delete certificates
  • Add or edit products
  • Import data (CSV or any format)
  • Download templates
  • Manage workflow states
  • Access Swagger admin API docs
  • Manage users, roles, companies, tags, or partners
  • See the Actions column on any table

Partner User Restrictions

Same restrictions as External, except data is scoped by partner program instead of company. A Partner user can see certificates from multiple companies as long as those certificates are tagged with their partner program.

5. Data Filtering Rules

5.1 Certificate Filtering

Certificate data filtering happens at the API query level (server-side, not client-side). It cannot be bypassed by URL manipulation or browser dev tools.

RoleSQL Filter AppliedResult
Admin / AnalystNoneAll certificates returned
ExternalWHERE CompanyId IN (user's company IDs)Only their company's certificates
PartnerWHERE Partner IN (user's partner names)Only partner-tagged certificates across all companies
PublicWHERE Status is publicly visible AND not expiredOnly active, public certificates
Zero-data case: If an External user has no company associations, or a Partner user has no partner associations, the query returns zero results. The system adds WHERE false to the query, guaranteeing an empty result set. This is by design.

5.2 Product Filtering

RoleFilter
ExternalProducts where CompanyId matches user's company associations. Products without a company are excluded.
PartnerProducts from companies that have certificates tagged with the partner's program.
Admin / AnalystAll products, no filter.

5.3 Filter Options & Autocomplete

The sidebar filters (Certification Type, Product Category, Company, Country, Tags) and the search autocomplete are also scoped to the user's data access level.

  • External user: Company filter only shows their own company. Certification type filter only shows types that appear in their company's certificates. Autocomplete suggestions only return matches from their data.
  • Partner user: Filter options reflect only data within their partner scope.
  • Admin/Analyst: All filter options from all data.
Why this matters for testing: If you log in as an External user and the Certification Type filter shows only 2 options, that's correct — it means their company only has certificates of those 2 types. It's not a bug; it's scoping working correctly.

5.4 CSV Export Scoping

When an External or Partner user clicks Export, the exported CSV contains only the data they can see. The same server-side filters that restrict the view also restrict the export. An External user cannot export another company's data by modifying the export URL.

9. Real-World Test Scenarios

Scenario A: Client Representative Reviews Their Certificates

User: External (assigned to "CertainTeed Insulation Group")

1

Log in with External account. Verify landing on External Tile View.

2

Verify only CertainTeed certificates appear. Note the certificate count.

3

Switch to List view. Verify the Company column shows only "CertainTeed Insulation Group".

4

Use search to find a specific CertainTeed certificate number. It should appear.

5

Search for a certificate belonging to another company (e.g., "Amazon"). Should return no results.

6

Click a certificate tile to view details. Verify no Edit/Delete buttons.

7

Download the certificate PDF. Verify it downloads successfully.

8

Click Export. Open CSV. Verify all rows are CertainTeed certificates.

9

Navigate to Product Management. Verify only CertainTeed products shown.

10

Verify no Actions column and no Add button on Product Management.

Scenario B: Amazon Partner Reviews Certificates Across Companies

User: Partner (assigned to "Amazon" partner program)

1

Log in with Partner account. Verify landing on External Tile View.

2

Verify certificates shown are tagged with Partner = "Amazon".

3

Switch to List view. Check the Company column — certificates may come from multiple companies (this is correct).

4

Verify no certificates appear with Partner = "Novi" or Partner = "None".

5

Click Export. Verify CSV only contains Amazon-partnered certificates.

Scenario C: Admin Verifies External User's Scoping

User: Admin (verifying an External user's experience)

Log in as Admin. Go to Administration > User Management.

2

Find the External user. Note their assigned Company (e.g., "Amazon").

3

Go to Internal Certificate Tile View. Filter by that company. Count results.

4

Log out. Log in as the External user.

5

Count the certificates shown. Should match the admin's filtered count for that company.

6

If counts don't match, investigate whether the mismatch is due to certificate status filtering (External view may hide certain statuses).

10. Troubleshooting

External user sees zero certificates

CheckHow to Verify
User has no company associationLog in as Admin > User Management > check the user's Company field. If blank, assign a company.
Company has no certificatesLog in as Admin > Internal Tile View > filter by that company. If zero results, the company simply has no certificates yet.
All certificates are in draft/inactive statusExternal view may filter out non-public statuses. Check certificate statuses as Admin.

External user sees certificates from wrong company

CheckHow to Verify
User assigned to multiple companiesAdmin > User Management > verify company associations. User may legitimately have multiple companies.
Certificate has wrong CompanyIdAdmin > Edit the certificate > check the Company field. It may have been assigned to the wrong company.

Partner user sees zero certificates

CheckHow to Verify
User has no partner associationAdmin > User Management > check the user's Partner assignment.
No certificates tagged with that partnerAdmin > Internal Tile View > filter by Partner. If no certs have that partner tag, none will show.

Permission changes not taking effect

The user must log out and log back in. Role claims are set at login time and cached in the session. Changes to roles, permissions, or company associations do not take effect until the next login.

External user gets 403 error on a page they should access

CheckHow to Verify
User role is not "External"Verify user's role in User Management. Must be exactly "External" for ExternalAccess policy.
Trying to access internal-only pageCheck if the URL is for an internal route (e.g., /Certificate/CertificateTileViewInternal). External users should use the External version.
