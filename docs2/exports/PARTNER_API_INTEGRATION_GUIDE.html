1. Quick Start

Three steps to get your first data:

1 Get your API key from GreenCircle Certified (format: gcc_partner_[64-character hash]).

2 Make your first request:

curl -X GET "https://[production-domain]/api/v1/certificates/gs1" \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Accept: application/json"

3 You'll receive a JSON response containing the certificates tagged to your partner account — including product identifiers (GTIN, MPN, UPC, EAN, SKU), certification details, and PDF download links.

Integration model: You pull data from GCC. GCC does not push to you. Call the API on your own schedule — continuously, nightly, or weekly — to retrieve current certification data. Each call returns the full certificate set visible to your account. Your system is responsible for determining what is new, changed, or removed since your last pull.

2. Authentication

Every request requires the X-API-Key header:

X-API-Key: gcc_partner_[your key — delivered separately]
Key handling. Your API key is a bearer credential — anyone holding it can read your certificate data. Store it in a secrets manager or environment variable, never in source control, ticket text, or email bodies. GCC delivers keys by secure channel only and never embeds them in documentation. If a key is exposed, contact GCC immediately for rotation.
Response CodeMeaningAction
200SuccessProcess the response
401Invalid or missing API keyCheck your key in the X-API-Key header
403Endpoint not permittedContact GCC support
404Resource not foundVerify certificate number or product ID
429Rate limit exceededWait and retry with exponential backoff
500Server errorContact GCC support with request details

Rate Limit

Partner API keys are limited to 200 requests per hour. Each request returns up to 100 certificates, so a full pull of the certificate database costs one request per 100 records.

Every response carries the current state of your allowance:

HeaderMeaning
X-RateLimit-LimitYour ceiling for the current window (200)
X-RateLimit-RemainingRequests left in the current window
X-RateLimit-ResetUnix timestamp when the window resets

The window is a fixed clock hour (UTC), not a rolling window — the allowance resets on the hour rather than 60 minutes after your first call. Exceeding the limit returns 429 with a Retry-After header. Read X-RateLimit-Remaining and pace accordingly rather than retrying into the limit.

BLOCKED — do not send this guide yet The server does not yet honour 200/hour. Rate limiting currently runs before authentication, so partner keys are throttled as anonymous traffic at 100 requests/hour, bucketed by IP address rather than by key — and that is what X-RateLimit-Limit actually returns today. The 200/hour figure above is the agreed target (Shawn, 2026-08-06), not current behaviour. Tracked as DEF-345; publishing this section before that fix ships hands a partner a number we do not honour. Delete this block once DEF-345 is verified.

3. API Endpoints

Base URL: https://[production-domain]/api/v1

GET /certificates/gs1 Recommended
List all certificates in GS1 JSON-LD format, following the GS1 US Certification Data Model. Product identifiers are always included; GTIN is promoted to a top-level field and other identifier types appear under additionalTradeItemId.
Parameters: pageNumber (default 1), pageSize (default and maximum 100), searchTerm, sortBy
GET /certificates/gs1/{certNumber}
Get a single certificate by certificate number in GS1 format.
Example: /certificates/gs1/24-0366
GET /certificates
List all certificates in standard JSON format.
Parameters: pageNumber, pageSize, searchTerm, sortBy, sortDescending, includeProductIds (boolean — set true to include product identifiers)
GET /certificates/number/{certNumber}
Get a single certificate by certificate number in standard JSON format. Use this to validate a brand-provided certificate or license number against the GCC ledger.
GET /certificates/search/productid
Find certificates by product identifier.
Parameters: productId (required), type (optional — GTIN, UPC, EAN, MPN, SKU, ASIN, ISBN; omit to search all types)
Example: /certificates/search/productid?productId=00012345678901&type=GTIN
GET /certificates/search
Search certificates by free-text term and/or date ranges.
Parameters: term, effectiveDateFrom, effectiveDateTo, expirationDateFrom, expirationDateTo, plus pagination parameters
GET /certificates/expiring
List certificates expiring within a given window — useful for scheduling revalidation of claims before they lapse.
Parameters: days (default 30), plus pagination parameters
GET /certificates/{certNumber}/download
Download the certificate PDF document. Returns application/pdf.

Certificate Status and Validity

The API expresses validity by presence, not by a status value. The status field is always the literal string "Active" on every certificate you receive. It is not a variable to branch on — it never carries any other value for a partner key.

What varies is whether the certificate appears at all. GCC tracks an internal certificate lifecycle, and only the states that mean "currently certified" are exposed to partners. Everything else is filtered out of list responses and returns 404 on single-certificate lookups.

What you receiveWhat it means
Certificate present, status: "Active"Currently certified. Safe to badge, or to confirm a brand's claim.
Certificate absent from the list / 404 on lookupNot currently certified — or not associated with your partner account.
Absence does not tell you why. A certificate you cannot see may have expired, may be on hold, may be withheld as confidential, may still be in draft, may never have existed, or may simply not be linked to your partner account. These cases are deliberately indistinguishable: collapsing them prevents your key from being used to enumerate certificates outside your scope. If you need to know why a specific certificate is not visible, ask GCC — do not infer it from the response.

There is no "revoked" state. GCC's lifecycle has no revocation status, so a revoked certificate can never be reported as revoked. Withdrawal of certification is expressed the only way the contract allows: the certificate stops appearing. Treat disappearance as authoritative.

Expiry. expirationDate is returned on every certificate, so you can see an upcoming expiry in advance. But note the asymmetry — once a certificate actually moves to an expired state it leaves the API entirely rather than appearing with an expired status. Do not wait to observe a status change that will never arrive; re-pull on your schedule and treat anything that has dropped out as no longer certified.

Internal — confirm scope, then delete This documents current behaviour (active-only), which is option (a) of the original open decision. Internally: the filter is CertificateStatusHelper.PublicStatuses = {Client Approved - Paid, Republished} applied at Controllers/Api/v1/CertificatesController.cs:173,201 for lists and :388,442 for single lookups; the literal "Active" is set at :251,315. Eight internal states exist and none of them is "revoked."

If this partner's use case is claim validation rather than badging, confirm that presence/absence is sufficient for them. Novi's guidance, for example, asks for Valid / Expired / Revoked-or-invalid as distinct values — which this contract cannot supply. That is raised as CR-035 (proposed, not built): it changes the response filter, the frozen /api/v1/certificates* shape, and — because no "revoked" state exists — potentially the 8-state workflow itself, so it needs client decisions and Amazon sign-off. Do not promise a partner anything beyond the table above until CR-035 is resolved.

5.4 Validate a Brand-Provided Certificate Number

Request

GET /api/v1/certificates/number/24-0366
X-API-Key: YOUR_API_KEY

Returns the certificate record if it exists and is visible to your account; returns 404 otherwise.

Reading the result. A 200 confirms the brand's claim: that certificate number is currently certified and associated with your account. A 404 means the claim cannot be confirmed — which is not the same as the claim being false. It collapses several distinct cases: expired, on hold, confidential, draft, never issued, mistyped, or valid but not linked to your partner account. See Certificate Status and Validity in §4 before deciding what action a 404 should trigger on your side; in particular, a 404 is not evidence of revocation.

7. Pagination

The API returns certificate data in pages of up to 100 certificates per request. Use the pagination object in each response to determine whether more pages are available:

// Page 1
GET /api/v1/certificates?pageNumber=1&pageSize=100

// Check response
"pagination": {
  "totalCount": 250,
  "pageNumber": 1,
  "pageSize": 100,
  "totalPages": 3,
  "hasNext": true,      // more pages available
  "hasPrevious": false
}

// Page 2
GET /api/v1/certificates?pageNumber=2&pageSize=100

Loop until hasNext is false.

8. Security & Access Scope

ControlDetails
TransportHTTPS/TLS required for all requests
AuthenticationAPI key via X-API-Key header
Data IsolationYour key returns only certificates associated with your partner account. Data belonging to other partners is not accessible, including on certificates shared across multiple partners — co-partner names and their product identifiers are removed from your responses.
Status FilterOnly currently-certified certificates are returned; everything else is filtered out of lists and returns 404 on lookup. status is always "Active". See §4.
Rate Limiting200 requests/hour per partner key; see §2
Key ManagementKeys are issued, rotated, and revoked by GCC administrators. Keys may be issued with an expiration date.
You will never receive: other partners' data, internal notes, workflow history, draft certificates, or GCC user information.

Supplier, Manufacturer and Parent-Company Data

None is transmitted, because none is held. GCC records the certified entity as a single flat company name. There is no supplier field, no manufacturer-identity field, and no parent-company or corporate-hierarchy relationship anywhere in the certificate record — so there is nothing of that kind for the API to disclose, and no field-level restriction is required to keep it out.

Specifically:

FieldWhat it is — and is not
company The name of the entity GCC certified — the brand holding the certification. A single value with no hierarchy above or below it. It is not a manufacturer identity and carries no parent-company reference.
productIds[].type = "MPN" Manufacturer Part Number — a product code supplied by the brand, in the same list as ASIN, UPC and GTIN. Despite the name it identifies a product, not a manufacturer, and reveals no manufacturing entity.
productIds[].productSku The certified company's own SKU for the item. Its own code, not a supplier's.

Company contact details, address, country and website are recorded by GCC for its own operations and are never included in any partner response — they are not part of the contract and no partner endpoint projects them.

If a partner's terms require a written assurance that manufacturer and parent-company information is not shared onward, this section is that assurance: the data is not in the payload because it is not in the system.
