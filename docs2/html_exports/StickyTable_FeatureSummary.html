Certificate Table View Enhancement

Sticky Headers, Sticky Scrollbar & Column Toggle

Prepared by: Anuki Consulting Date: March 12, 2026 Platform: GCC Certificate Management System

Overview

The certificate table view has been redesigned to improve usability when working with wide, data-rich tables. Users no longer need to scroll to the bottom of the page to find the horizontal scrollbar, and column headers remain visible at all times regardless of vertical scroll position.

Internal users also gain the ability to show or hide individual columns, with their preferences automatically saved between sessions.

Key Features

↕

Sticky Column Headers

Column headers pin to the top of the viewport as you scroll down through certificate rows. You always know which column you are reading.

↔

Sticky Horizontal Scrollbar

A visible scrollbar is always accessible at the top of the table. No more scrolling to the very bottom of a long list just to pan left and right.

⚙

Column Toggle (Internal)

Internal users can show or hide any data column via a dropdown with toggle switches. Reduces clutter and lets each user tailor the view to their workflow.

💾

Saved Preferences

Column visibility choices are saved automatically in your browser. When you return to the page, your preferred column layout is restored without any extra steps.

How It Works

Layout Architecture

The toolbar, horizontal scrollbar, and column headers are grouped into a single block that sticks to the top of the screen. The table rows scroll independently beneath this block. All three horizontal areas (scrollbar, headers, body) stay synchronized so they always align.

Sticky Block PINS TO TOP
  ├─ Toolbar Row        (results count, column toggle button)
  ├─ Scrollbar Row     (always-visible horizontal scrollbar)
  └─ Header Row        (column names with sort indicators)

Table Body SCROLLS VERTICALLY
  └─ Data Rows         (certificate records, infinite scroll)

Synchronized Scrolling

When you drag the sticky scrollbar left or right, the column headers and body rows move in sync. If you scroll the body area directly (e.g., via trackpad), the scrollbar and headers follow automatically. This three-way sync ensures all parts of the table always line up, regardless of how you scroll.

Column Toggle (Internal Users)

Clicking the Columns button in the toolbar opens a dropdown organized into four groups:

  • Core Fields — Certificate #, Type, Status, Dates
  • Company & Product — Company, Contact, Product Name, Category, Type, Subcategory
  • Location & Tags — Location, Country, External Tag, Internal Tag, Partner
  • Product IDs — ASIN, UPC, GTIN, EAN

Each column has a toggle switch. The Select and Actions columns are locked and always visible. A badge on the button shows the count of currently visible columns. Click Show All to reset.

How localStorage Is Used

localStorage is a built-in browser feature that lets a website save small amounts of data on the user's computer. It persists between page loads and browser sessions — the data stays until the user clears their browser data or it is explicitly removed by the application.

What Is Stored

Property Detail
Key gcc-cert-columns-internal
Value A JSON array of hidden column identifiers (e.g., column class names)
Size Typically under 200 bytes
Applies to Internal certificate table view only

Example

If a user hides the Contact and GTIN columns, the browser stores:

// Browser localStorage
Key:   "gcc-cert-columns-internal"
Value: ["tc-contact", "tc-gtin"]

When the user returns to the page, the application reads this value and automatically hides those two columns, restoring the user's preferred layout.

Behavior Details

  • Automatic save: Every time a column is toggled on or off, the preference is saved immediately. There is no "Save" button needed.
  • Automatic restore: When the page loads and when new rows are added via infinite scroll, hidden columns are re-applied to the new content.
  • Reset: Clicking "Show All" in the column dropdown makes all columns visible and clears the stored preference.
  • Browser-specific: Preferences are stored per browser. If a user switches to a different browser or device, they start with all columns visible.
  • No server communication: Column preferences are stored entirely in the browser. No data is sent to the server, and no user account or profile is required.
  • Graceful fallback: If localStorage is unavailable (e.g., private browsing mode in some browsers), the feature still works — columns can be toggled during the session, but preferences are not saved between visits.
Privacy note: The only data stored is a list of hidden column names (e.g., "tc-contact", "tc-gtin"). No personal information, certificate data, or user identifiers are saved to localStorage.
Clearing browser data: If a user clears their browser's site data or cookies, saved column preferences will be removed. All columns will return to their default visible state on the next visit.

Future Considerations

  • User profiles: If user accounts with server-side profiles are added in the future, column preferences could be migrated from localStorage to the user profile so they follow the user across browsers and devices.
  • External column toggle: The column toggle capability can be extended to external users if needed — the underlying architecture supports it.
  • Column reordering: The current architecture uses shared CSS width classes between headers and body, which could support drag-to-reorder columns in a future enhancement.
